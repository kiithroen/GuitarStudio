# 화면과 조작

툴바, 표기, 단축키, 메트로놈 클릭에 대한 결정이야. 사용자 설명은 [사용 안내](usage.md)에 있어.

## 툴바와 콘솔

- 2026-10-19 결정: 악보 바로 위 `#scoreToolbar`에 시작 버튼 `#compactPlayBtn`과 곡 선택 `#compactSongSelect`를 일반·콤팩트 뷰 모두 둬. 상단 패널의 중복 곡 선택 행은 지우지 않고 `hidden`으로 숨겨 DOM·테스트 호환을 지켜.
- 원래 시작 버튼 `#playBtn`은 hidden으로 남아 있어. Space 단축키(`src/app.js` keydown 핸들러)와 스모크 테스트가 이 버튼을 누르니 지우지 마.
- 2026-10-19 결정: 콘솔은 2열 그리드야. 셋째 박스를 없애고 기타 시뮬레이션 토글 `#guideSoundBtn`을 첫째(템포) 박스 헤더의 콘서트홀 버튼 옆으로 옮겨 `.fx-toggle` 스타일을 써.
- 2026-10-19 결정: 툴바가 여러 줄로 접히지 않게 640px 이상에서 `flex-wrap: nowrap`을 주고 `#scoreClickHint`를 숨겨. 원본 상태에서는 '원본 악보' 안내 줄을 없애고, 임시 악보·수정 초안이 아니면 `#scoreDraftControls` 전체를 숨겨 악보를 위로 붙여.
- 2026-10-19 결정: `#rewindToFirstBtn`(Home)은 긴 악보를 스크롤하다 한 번에 처음으로 돌아가려고 둔 거야. `resetToFirstMeasure`가 커서를 첫 마디로 돌리고, 반복 구간 시작이 첫 마디를 벗어나 있으면 전체 곡 기준으로 맞추고, `#structuredScoreWrap`·`#imgStageScroll`를 맨 위로 부드럽게 스크롤해.

- 2026-10-19 결정: 곡 선택 목록(`#songSelect`, `#compactSongSelect`)은 내장곡을 레벨별 묶음(`Lv.1 입문` 등)으로 보여 줘. 두 목록 모두 `src/app.js`의 `appendBuiltinSongGroups` 하나로 만들어. 레벨 기준은 [내장곡 출처](builtin-sources.md)의 레벨 절에 있어.

## 단축키와 안내

- 단축키는 `src/app.js`의 keydown 핸들러 한 곳에서 처리하고 한글 자판 키도 같이 받아. 입력 칸에 포커스가 있거나 모달이 열려 있으면 무시해. 키를 바꾸면 `#helpModal` 안내도 같이 고쳐.
- 2026-10-19 결정: 헤더의 `#helpModalOpenBtn`과 `?` 키로 `#helpModal` 조작 안내(연습 제어, 오디오·음색, 악보 모드, 마우스 조작)를 열어.

## 메트로놈 클릭

2026-10-19 결정: `appState.clickMode`(`all`/`countin`/`off`)로 고르고 localStorage 앱 설정에 저장해. 기본값은 기존 동작인 `all`이야. `off`는 카운트인 마디도 건너뛰어. 카운트인 동안 화면에 진행 표시가 없어서 소리 없는 한 마디 대기는 앱이 멈춘 것처럼 보이기 때문이야. 구간 반복으로 첫 마디에 돌아갈 때는 어느 모드든 카운트인을 다시 하지 않아.

## 음이름 표기

- 2026-10-19 결정: 표기 문자열은 `src/score.js`의 `formatBeatPitchLabel`·`getNoteDisplayName`이 SSOT야. 화면에 CDE와 도레미가 섞여 있어서 기본을 CDE로 통일하고 헤더에 `도레미 표기 / CDE 표기` 전환 버튼을 뒀어.
- 2026-10-19 결정: 음이름에는 음높이만 써. `!`·`~` 주법은 원문 메타데이터로 남고 재생에도 쓰이지만, 음이름 뒤 기호나 주법 색으로 보여 주면 시각 요소가 과밀해져서 뺐어. `test/test-score.js`가 주법이 달라도 표기가 같은지, formatter가 악보 객체를 바꾸지 않는지 확인해.

## 박자 카드

- 2026-10-19 결정: 분할음이나 화음이 많으면 글자가 카드 밖으로 넘쳐서, `maxSubParts`에 따라 마디 카드 최소 너비를 늘리고 음이름 글자 수에 따라 `b-ko-dense`·`b-ko-ultra` 클래스로 글자를 줄여.
- 2026-10-19 결정: 카드 공간을 아끼려고 오른손 운지 라벨에서 '오른손 ' 접두사를 빼고 기호만 써(`5줄 p + 1줄 a`, `i / m`). `active-beat`일 때 오른손 운지와 서브 표기의 대비·굵기를 올려 재생 중에도 읽히게 해.

## TAB과 지판

- TAB 칸의 명시 왼손 운지는 프렛 숫자 뒤 괄호로 붙여(`1C4@2` → `1(1)`, `C4@2` → `1`). 운지가 원문에 없으면 괄호를 그리지 않아.
- 2026-10-19 결정: 지판 목표음은 개방현과 프렛 모두 같은 `target-note` 배지를 써. 개방현 label만 색을 바꾸던 방식이 어긋났기 때문이야.
- 2026-10-19 결정: TAB은 마지막 현 pill 그림자까지 보이게 하단 여백을 두되 격자·현 이름·배경선 정렬을 유지해. 6번 줄 하단이 잘렸기 때문이야.
- 2026-10-19 결정: 코드 지판(파란 점)의 개방현(`fret === 0`)은 글자색 대신 프렛과 같은 `.fb-marker.chord-tone` 원형 마커로 `0`을 그려. 연주음(초록) 마커와 겹치면 container를 비우고 다시 그리는 기존 흐름에 따라 연주음이 보여.

## 확인 표시

2026-10-19 결정: 원문에 확인 표시 `?`가 있는 칸은 TAB과 박자 카드 모두 `.beat-cell.is-uncertain`(경고색 안쪽 테두리와 배경)으로 칠하고 툴팁 끝에 `확인 필요(?)`를 붙여. 악보 툴바의 `#uncertainBadge`는 확인 표시가 있는 칸 수를 `확인 N곳`으로 보여 주고, 0이거나 이미지 악보면 숨겨. 개수는 `src/score.js`의 `countUncertainBeats`만 세. 긴 곡에서 표시를 놓치지 않게 하려고 둔 거야. CSS 규칙은 `.beat-cell.tab-cell`(투명 배경)과 `.beat-cell.arp-group-start`(구분 그림자)보다 뒤에 두고 `:not(.active-beat)`로 특이도를 올려. 앞에 두면 TAB 보기에서 배경이 지워지고 6·8·9칸 곡의 그룹 첫 칸에서는 표시가 통째로 사라져. `arp-group-start` 칸은 구분 그림자와 경고 테두리를 한 `box-shadow`에 합쳐. 재생 중 활성 칸은 활성 표시가 이겨. 문법은 [악보 문법](score-format.md)의 확인 표시를 봐.
