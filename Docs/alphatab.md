# alphaTab 보기

연습 화면의 곡을 alphaTab 플레이어로 눈으로 비교하는 새 탭 보기 창이다. 악보 입력과 연습 화면이 쓰는 우리 오선·TAB과 책의 악보를 견줄 때 다른 엔진이 그린 같은 곡을 한 번 더 보려는 용도다. 연습 기능(구간 반복, 메트로놈, 가이드음, 지판)과 소리는 우리 앱이 맡고, alphaTab은 미리보기만 한다.

구성은 이렇다.

| 파일 | 역할 |
|---|---|
| `src/score-to-alphatex.js` | 우리 악보 → alphaTex 변환기(`GuitarAlphaTex.toAlphaTex`). DOM 없는 순수 함수이고 Node에서도 돈다 |
| `alphatab.html`, `src/alphatab-view.js` | 보기 창. `app.js`를 불러오지 않는다. 변환하고 alphaTab 플레이어를 띄운다 |
| `vendor/alphatab/` | alphaTab 1.8.4(MPL-2.0). 브라우저 UMD(`dist/alphaTab.min.js`, 전역 `alphaTab`), worker·worklet, Bravura 글꼴, sonivox 사운드폰트 |
| `test/test-score-to-alphatex.js` | 변환기 테스트. vendor의 alphaTab을 `require`해서 변환 결과를 가져온 모델 필드까지 확인한다 |
| `tools/score-to-alphatex.js`, `tools/alphatab-to-score.js` | 우리 악보 ↔ alphaTab 양방향 명령줄 도구. [명령줄 도구](#명령줄-도구) |
| `tools/build-scores.js` | 폴더의 `.tex` 원본을 시트용 6열 TSV로 바꾸는 도구. 같은 이름의 `.tex`가 없는 Guitar Pro 파일은 먼저 `.tex`로 만든다. [원본은 alphaTex](#원본은-alphatex) |
| `tools/gp-to-alphatex.js` | Guitar Pro 파일의 기타 트랙 하나를 alphaTex 원본(`.tex`)으로 쓰는 도구. [원본은 alphaTex](#원본은-alphatex) |
| `test/test-alphatab-tools.js`, `test/fixtures/alphatab/` | 명령줄 도구 테스트와 예제(손으로 짠 alphaTex, MusicXML, 브랜치 alphaTex 16곡) |

## 원본은 alphaTex

곡의 원본은 alphaTex이고, 시트의 우리 악보(5열)는 그 alphaTex에서 만들어 낸 결과물이다. 길은 둘이다: 사진 → alphaTex → 우리 악보, alphaTex → 우리 악보. 우리 문법이나 플레이어가 좋아지면 변환기만 다시 돌려 원본에서 정보를 다시 꺼낸다.

```text
드라이브 GuitarScores/곡.gpx (Guitar Pro. 같은 이름의 .tex가 없을 때만)
  → node tools/build-scores.js <폴더>가 곡.tex를 만든다(첫 기타 트랙만 alphaTex로 쓴다)
드라이브 GuitarScores/곡.tex
  → node tools/build-scores.js <폴더>
  → 곡.tsv (6열: 제목, 칸 수, BPM, 설명, 악보, alphaTex 원본)
  → 시트의 Apps Script (F열에 alphaTex)
  → 시트 → 앱 · 보기 창
```

| 정보 | 처리 |
|---|---|
| 음높이·길이·붙임줄·셋잇단·코드 이름·운지·주법·카포·템포·박자표 | alphaTex에 들어간다([변환 규칙](#변환-규칙)) |
| 마디 메모와 곡 설명 | alphaTex에 들어간다. 마디 메모는 그 마디 첫 박의 박 효과 `txt "…"`, 곡 설명은 머리 `\notices "…"` |
| 버림: 아포얀도 `!` | alphaTex를 거치면 사라진다. 교본에도 음마다 붙은 아포얀도 표시는 없고 "선율을 아포얀도로" 같은 메모로만 쓰여서다 |
| 버림: 확인 표시 `?` | 사라진다. 필요 없다고 사용자가 정했다 |
| 버림: 왼손 `0` | 사라진다. 내장곡 510곳 모두 프렛 0(개방현)이라 프렛 0과 같은 정보이고 소리도 위치도 더하지 않아서다 |

- 2026-10-20 결정: alphaTex를 악보의 원본으로 둔다. 우리 문법이 바뀌거나 플레이어가 좋아져도 변환기만 다시 돌리면 되고, 우리 악보에서 alphaTex로 되돌리면 잃는 정보(성부, 실제 길이, 도돌이)를 원본에 그대로 둘 수 있어서다. 아포얀도만 보충 파일로 살리는 안도 있었지만 교본에 음별 표시가 없어 뺐다. 위 표의 세 가지는 alphaTex를 거치면 버린다.
- 원본 `.tex`를 고치는 일은 Claude가 PC에서 하고 `tools/build-scores.js`로 다시 변환한다.
- Guitar Pro 파일(`.gp` `.gp3` `.gp4` `.gp5` `.gpx`)을 폴더에 넣고 `build-scores`를 돌리면 같은 이름의 `.tex`가 없는 것마다 `.tex`가 생기고 이어서 `.tsv`가 생긴다. 만들어진 `.tex`가 원본이 되고 `.gp`는 지우지도 고치지도 않는다. 다른 트랙은 `node tools/gp-to-alphatex.js <파일> --track n`으로 만든다(명령줄 도구 절).
- 2026-10-20 결정: 원본 alphaTex가 있는 곡(곡 객체에 `alphaTex`가 있는 곡)은 앱에서 제자리에서 고치지 않는다. 사용자가 악보 입력 화면에서 고쳐 돌아오면 원본을 잃은 것으로 보고, 우리 악보만 담은 `(사본)` 곡을 새로 만들어 저장한다(제목 규칙은 [화면과 조작](ui.md)). 원본 곡은 그대로 남는다. 칸 수를 바꿔 돌아와도 같다(제목은 원래 곡의 `(사본)`, 칸 수는 고친 악보의 것). 앱은 드라이브에 쓰지 못하고, 우리 악보에서 alphaTex로 되돌리면 성부·실제 길이·도돌이 같은 원본 정보를 잃기 때문이다.

## vendor로 둔 이유

alphaTab은 `codex/alphatab-player` 실험 브랜치에서 가져온 1.8.4다. 번들러가 없는 정적 앱이라 CDN 대신 저장소에 두었고(GitHub Pages에서 같은 출처로 서빙), vendor 파일은 고치지 않는다. 플레이어는 이 보기 창에서만 불러온다. 앱 기본 화면(`index.html`, `score-input.html`)은 alphaTab을 로드하지 않고 시작 속도와 소리가 그대로다.

## 쓰는 법

1. 연습 화면 머리의 `alphaTab` 단추(`#openAlphaTabBtn`, `단축키 안내` 옆, 구조화 곡일 때만 보인다)를 누른다. 지금 곡(수정 초안이면 초안 내용)을 localStorage `gs.alphaTab.view`에 `{ title, beats, bpm, capo, description, lines, savedAt }`로 넣고 `alphatab.html`을 새 탭으로 연다. `description`은 곡의 `badge`(시트 설명 열)다. 곡에 원본 `alphaTex`가 있고 고친 초안이 아니면(`scoreDrafts.status`의 `dirty`·`temporary`가 모두 거짓이면) `alphaTex`도 넣는다. 연습은 멈추지 않는다.
2. 보기 창은 그 값을 읽어 그린다. `alphaTex`가 있으면 변환하지 않고 그대로 읽어 그리며 머리의 작은 꼬리표(`#atSource`)에 `원본 alphaTex`가 보인다. 없으면 우리 악보를 변환해 그리고 꼬리표는 `우리 악보에서 만든 미리보기`다. 원본 alphaTex를 alphaTab이 읽지 못하면 상태 줄에 알리고 변환 미리보기로 대신 그린다. 값을 지우지 않아서 새로고침해도 같은 곡이다. 값이 없거나 모양이 틀리면 상태 줄에 안내만 한다. 변환이나 alphaTab 읽기가 실패하면 이유를 상태 줄에 보인다.
3. 조작은 머리 한 줄에 있다: 곡 제목, `재생`/`일시정지`(Space), `처음으로`, 빠르기(50·75·100%), 보기(`오선+타브`·`타브`·`오선`), 상태 줄. 보기를 바꾸면 다시 그린다.

색은 `src/base.css` 토큰(`--fg`, `--muted`)에서 읽어 alphaTab 표시 색(`mainGlyphColor`, `staffLineColor` 등)에 넣고, 시스템 색 구성이 바뀌면 다시 읽는다. 소리는 alphaTab의 사운드폰트라 앱의 합성음과 다르다.

## 변환 규칙

배치는 `GuitarStaffLayout.layoutScore`의 결과 하나만 쓴다. 코드 이름만 `GuitarParser.parseScore`의 마디 `chord`에서 읽는다. 표의 alphaTab 모델 필드는 `vendor/alphatab/dist/alphaTab.core.mjs`의 alphaTex 파서 코드에서 찾은 표기를 Node에서 가져와 `test/test-score-to-alphatex.js`가 확인한 것이다.

| 우리 악보 | alphaTex | alphaTab 모델 |
|---|---|---|
| 곡 제목 | `\title "…"`(따옴표·역슬래시 이스케이프) | `score.title` |
| BPM(분당 칸 수) | `\tempo (n)`. 한 칸이 4분음표면 BPM, 8분음표면 BPM의 절반(`getGridInfo(beats).slotQuarterLength`) | `score.tempo`(4분음표 기준) |
| 칸 수 | `\ts (분자 분모)`(`getGridInfo`) | `masterBar.timeSignatureNumerator`·`Denominator` |
| 카포 | `\capo n`(0이면 안 적는다). 프렛은 카포 기준 그대로 | `staff.capo`. 실음 `note.realValue` = 프렛 + 카포 + 개방현 |
| 음 | `프렛.줄`(우리 줄 번호와 같다: 1번 줄이 높은 미). 화음은 `(음 음 …)` | `note.fret`, `note.string`(alphaTab은 높은 줄이 큰 수) |
| 음 길이 | 온 1, 2분 2, 4분 4, 8분 8, 16분 16, 32분 32를 `.길이`로 | `beat.duration` |
| 점음표 | 박 효과 `d`(하나), `dd`(둘) | `beat.dots` |
| 셋잇단 | 박 효과 `tu 3` | `beat.tupletNumerator` 3, `tupletDenominator` 2 |
| 쉼 | `r.길이`. 마디가 통째로 쉬면 `r.1`(박자와 상관없이 마디 길이) | `beat.isRest`, `beat.isFullBarRest` |
| 붙임줄로 이어진 뒤 토막 | 음 효과 `t`(프렛은 그대로 적는다) | `note.isTieDestination`, `note.tieOrigin` |
| 자연 하모닉스 `h` | 음 효과 `nh`. 프렛은 손 대는 프렛 | `note.harmonicType` = Natural, `note.realValue`가 울리는 음 |
| 슬러 `s` | 출발 음(앞 음)에 음 효과 `h`. 마디를 넘으면 출발 마디의 음, 붙임줄로 나뉜 음이면 마지막 토막 | `note.isHammerPullOrigin`, `note.hammerPullDestination` |
| 슬라이드 `g` | 출발 음에 음 효과 `sl` | `note.slideOutType` = Legato, `note.slideTarget` |
| 왼손 운지 1~4 | 음 효과 `lf 2`~`lf 5`(alphaTab은 1이 엄지라 한 칸 밀린다). 0은 안 적는다 | `note.leftHandFinger` = IndexFinger~LittleFinger |
| 오른손 운지 `:p :i :m :a` | 음 효과 `rf 1`~`rf 4` | `note.rightHandFinger` = Thumb~AnnularFinger |
| 롤 `~` | 박 효과 `ad` | `beat.brushType` = ArpeggioDown |
| 마디 코드 이름 | 마디 첫 박의 박 효과 `ch "이름"`(`[-]`이면 없다) | `beat.chordId`, `staff.chords`의 `name` |
| 마디 메모 | 마디 첫 박의 박 효과 `txt "…"`(따옴표·역슬래시 이스케이프는 제목과 같다) | `beat.text` |
| 곡 설명 | 머리 `\notices "…"`(입력의 `description`이 있을 때) | `score.notices` |
| 마디 | ` \|` | 마디마다 `masterBar` 하나 |
| 빈칸 `_` | 내보내지 않는다(시간 0). 첫 마디의 앞쪽 빈칸은 그 마디를 못갖춘마디 `\ac`로 쓴다. 그 밖의 빈칸이 든 마디는 그 마디 첫 음 앞에 `\ts (n d)`(n은 빈칸이 아닌 칸 수, d는 칸 음표: 4분음표 칸이면 4, 8분음표 칸이면 8)를 적고, 다음 마디가 원래 박자면 그 마디 앞에 원래 `\ts`를 다시 적는다. 마지막 마디도 같다 | `masterBar.isAnacrusis`, `masterBar.timeSignatureNumerator`·`Denominator` |

- 붙임줄 도착 음에는 운지를 달지 않는다. 다시 치지 않는 음이라서다. 하모닉스(`nh`)와 슬러·슬라이드 출발 표시는 도착 음이 마지막 토막일 때 그 토막에 단다.
- 롤은 `ad`다(아래 결정 참조). 화음 첫 토막에만 달리고(배치가 롤을 첫 토막에만 싣는다) 붙임줄로 이어진 뒤 토막에는 없다.
- 빈칸이 든 마디의 음 길이는 `layoutScore`가 마디를 실제 시간 경계로 잘라 준 결과 그대로라, 마디의 박 길이 합은 빈칸이 아닌 칸 수와 같다. 첫 마디가 아닌 마디의 앞쪽 빈칸도 `\ts` 변경으로 쓰므로, 되돌리면(`alphatab-to-score.js`) 뒤쪽 빈칸이 된다.
- 코드 이름은 alphaTab이 소문자로 바꾼 값을 코드 키로 써서 `CM7`과 `Cm7`이 같은 코드가 된다. 키가 겹치는 다른 이름 뒤에는 폭이 없는 글자(`GuitarAlphaTex.CHORD_NAME_PAD`)를 붙여 가른다.

## 넣지 않는 것

아포얀도 `!`, 확인 표시 `?`, 왼손 `0`, 조표(`key`), 변칙 조율(조율은 표준만)은 변환하지 않는다([원본은 alphaTex](#원본은-alphatex)). 눈으로 대조하는 데 필요한 음높이·길이·운지·주법만 옮긴다.

## 결정

- 2026-10-20 결정: 연습 기능과 소리는 우리 앱이 맡고, alphaTab은 눈으로 비교하는 미리보기로만 둔다. alphaTab을 앱의 연주 엔진으로 바꾸는 실험은 `codex/alphatab-player` 브랜치에 남아 있고 main은 기존 엔진을 쓴다.
- 2026-10-20 결정: 변환은 `layoutScore` 결과 하나만 쓴다. 음 길이·점·붙임줄·셋잇단·슬러/슬라이드 항목·롤 첫 토막을 변환기에서 다시 셈하면 오선 미리보기와 어긋나는 곳이 생기고, 오선 미리보기가 음 길이를 `GuitarRhythm.annotate` 결과 하나로만 쓰는 이유([오선 미리보기](staff-notation.md))와 같다. 배치가 오류면 그 오류를 그대로 돌려준다.
- 2026-10-20 결정: 롤은 `au`가 아니라 `ad`로 옮긴다. 이름이 반대로 보이지만, alphaTab의 `ad`(ArpeggioDown)가 아래 줄(낮은 소리)부터 굴린다. `ad`와 `au`를 같은 화음에 달고 alphaTab이 만든 MIDI 이벤트의 시작 순서를 보면 `ad`는 낮은 음부터, `au`는 높은 음부터였고(`test/test-score-to-alphatex.js`), 화면에서도 `ad`의 화살표가 위를 가리켰다(낮은 줄에서 높은 줄로, 우리 롤과 같은 방향).
- 2026-10-20 결정: `alphaTab` 단추는 악보 툴바(`악보 편집` 앞)가 아니라 머리 줄(`단축키 안내` 옆)에 둔다. 툴바에 넣으면 640px 폭 검사에서 `보기 선택`·`카포 배지`와 겹쳤다([화면과 조작](ui.md)).
- 2026-10-20 결정: 폭 500px 미만에서는 alphaTab 배율을 낮춰(`NARROW_SCALE`) 그린다. 배율은 불러올 때만 정한다. 375px에서도 가로로 넘치지 않지만 긴 곡 제목이 악보 머리의 제목 줄에서 잘린다(보기 창 안에서 가로 스크롤). 제목은 머리 줄에도 있다.
- 틀린 길: 처음에는 롤을 `au`로 옮기려 했다. 이름만 보고 정한 것이었고 위 확인으로 바로잡았다.
- 알려진 것: 재생을 시작하자마자 바로 멈추면 alphaTab 내부(`pause`)에서 `InvalidStateError`가 콘솔에 난다(소리가 실제로 시작되기 전에 멈출 때). `test/test-browser-smoke.js`는 재생 뒤 잠시 기다렸다 멈춘다. 이 오류는 vendor 코드 안이라 고치지 않았다.
- 안 돌려 본 것: 실제 폰(갤럭시 폴드7)에서의 보기·재생. 소리 품질은 확인하지 않았다.

## 명령줄 도구

우리 악보와 alphaTab 사이를 오가는 두 도구가 `tools/`에 있다. 앱 화면과 상관없이 `node`로 돌린다.

```powershell
node tools/score-to-alphatex.js <시트 한 행 TSV 파일 | --builtin <id>> [-o 출력.tex]
node tools/alphatab-to-score.js <입력 파일> [--track n(1부터)] [-o 출력.tsv]
node tools/build-scores.js <폴더> [--check]
node tools/gp-to-alphatex.js <입력.gp|.gp3|.gp4|.gp5|.gpx> [--track n(1부터)] [-o 출력.tex]
```

| | `score-to-alphatex.js` | `alphatab-to-score.js` |
|---|---|---|
| 방향 | 우리 악보 → alphaTex | alphaTex·Guitar Pro·MusicXML → 시트 한 행 |
| 입력 | 시트 한 행 TSV(`check-score.js`가 읽는 5열 또는 6열. 6번째 열은 쓰지 않는다), 또는 `songs.json`의 내장곡 id | `.tex` `.alphatex`, `.gp` `.gp3` `.gp4` `.gp5` `.gpx`, `.musicxml` `.xml` |
| 변환 | `GuitarAlphaTex.toAlphaTex` 하나만 쓴다. 카포는 `getSongCapo({ title, badge: 설명 })` | alphaTab이 읽은 모델을 `convertScore`로 시트 행(제목, 칸 수, BPM, 설명, 악보)으로 바꾼다 |
| 출력 | stdout, `-o`면 파일 | stdout, `-o`면 파일. 성공하면 `check-score.js`와 같은 검사(`GuitarParser.validateScore`)를 돌려 오류가 있으면 출력은 쓰되 오류 목록을 stderr에 낸다 |
| 종료 코드 | 0 성공, 1 변환 실패(TSV 검사에 걸림 포함), 2 사용법이 틀림(인자, 읽을 수 없는 파일, 없는 id, 한 행이 아닌 TSV) | 0 성공, 1 변환하지 않음·읽지 못함·검사 오류, 2 사용법이 틀림(인자, 읽을 수 없는 파일, 모르는 확장자) |

`build-scores.js`는 [원본은 alphaTex](#원본은-alphatex)의 흐름을 맡는다. 폴더 안(하위 폴더 제외) `*.tex`마다 `alphatab-to-score.js`와 같은 변환·검사(`GuitarParser.validateScore`)를 돌려 같은 이름의 `.tsv`를 쓴다. 한 행 6열은 제목, 칸 수, BPM, 설명, 악보, alphaTex 원본이고, 원본은 파일 내용의 줄바꿈·탭·연속 공백을 공백 하나로 편 것이다(따옴표 안은 그대로 두고, 따옴표 안에 줄바꿈이나 탭이 있으면 그 파일은 변환하지 않는다). 한 줄로 펴서 변환 결과가 달라지는 파일(줄 끝 주석 등)도 변환하지 않는다. UTF-8에 앞에 BOM, 끝에 줄바꿈 하나다. 변환·검사 오류가 있는 파일은 TSV를 쓰지 않고(기존 TSV는 그대로) 오류를 목록으로 보이며 종료 코드 1이다. `.tex`가 없는 TSV(손으로 만든 것)는 건드리지 않는다. `--check`는 쓰지 않고 보고만 한다. 마지막 줄은 `변환 n · 오류 n · 건너뜀 n`이다. 시트 셀 한 칸이 50,000자라 그보다 긴 alphaTex는 Apps Script가 F열만 비운다([시트 자동 가져오기](development.md#시트-자동-가져오기)).

`build-scores.js`는 폴더 안(하위 폴더 제외) Guitar Pro 파일 중 같은 이름(확장자를 뺀 이름)의 `.tex`가 없는 것마다 `gp-to-alphatex.js`의 `gpToAlphaTex`(기본 트랙)로 `.tex`를 만들고, 그 `.tex`를 이번 실행의 목록에 더해 위처럼 `.tsv`를 만든다. 로그는 `만듦: 곡.gpx → 곡.tex (트랙 n/m "이름")`이고 트랙이 둘 이상이면 아래에 트랙 목록을 들여 쓴다. 같은 이름의 `.tex`가 있으면 `건너뜀: 곡.gpx (.tex 있음)`을 찍고 건너뛴다(건너뜀 수에 더한다). 실패(트랙 없음, 비표준 조율 등)는 `오류: 곡.gpx`와 이유이고 `.tex`를 쓰지 않는다. `--check`는 아무 파일도 쓰지 않고 `.gp`를 메모리에서 alphaTex로 바꿔 변환까지 돌려 `확인: 곡.gpx → 트랙 n (m마디)`를 찍는다.

`gp-to-alphatex.js`는 읽기(`parseScoreBytes`)와 트랙 고르기(`selectStaff`, `--track`이 없으면 첫 표준 조율 6줄 기타 트랙)를 `alphatab-to-score.js`의 것 그대로 쓰고, 고른 트랙만 남긴 악보(`score.tracks = [고른 트랙]`)를 vendor alphaTab의 `AlphaTexExporter`로 쓴다. `\title`은 파일 이름에서 확장자를 뗀 이름이고, `notices`는 ` · `로 이은 [파일 안 제목이 비어 있지 않고 파일 이름과 다르면 `원제 <파일 안 제목>`, 파일 안 notices, `Guitar Pro 파일(<파일 이름>)에서 변환`]이다. 그 밖의 머리 정보는 건드리지 않는다. 출력은 BOM 없는 UTF-8, 줄바꿈 LF이고, 출력 파일이 이미 있으면 덮지 않고 종료 코드 1이다(손본 원본을 지키려고). 성공하면 `만듦: <출력> (트랙 n/m "이름")` 한 줄과(트랙이 둘 이상이면) 트랙 목록을 찍는다. 종료 코드는 0 성공, 1 변환하지 못함·출력이 이미 있음, 2 사용법이 틀림(인자, 읽을 수 없는 파일, `GP_EXTENSIONS`에 없는 확장자)이다. MusicXML은 범위가 아니다.

메시지는 한국어 `~습니다`체다. 읽는 쪽은 alphaTex가 `AlphaTexImporter`, 나머지가 `ScoreLoader.loadScoreFromBytes`(바이트에서 형식을 알아서 고른다)다. `--track`은 1부터 센 트랙 번호다(Guitar Pro 같은 프로그램과 같다). 생략하면 6줄 표준 조율 트랙이 먼저이고, 없으면 음높이가 있는 첫 트랙(줄·프렛 없이 음높이만 있는 트랙)이다. 6줄인데 표준 조율이 아닌 트랙뿐이면 줄 정보 없는 트랙으로 넘어가지 않고 이유와 함께 멈춘다. 트랙 목록은 오류 메시지에 1부터 나온다.

### 가져오기 규칙

`alphatab-to-score.js`가 alphaTab 모델에서 우리 악보를 만드는 규칙이다. 기대는 `test/test-alphatab-tools.js`가 확인한다.

| 항목 | 규칙 |
|---|---|
| 칸 | 박자표를 `src/score-prompt.js`의 [문법 5] 표대로 고른다. 2/4·3/4·4/4는 2·3·4칸(4분음표), 2/2는 4칸, 3/8은 3칸(8분음표), 6/8·9/8은 6·9칸(8분음표)인데 BPM이 상한(`BPM_MAX`)을 넘으면 2·3칸(점4분음표, 칸 안 3분할), 12/8은 4칸(점4분음표). 표에 없는 박자와 6줄 표준 조율(`GuitarParser.STRINGS`의 개방현)이 아닌 곡은 변환하지 않고 이유를 낸다. 카포는 설명 열 `Capo n`. 곡 중간 박자 변경: 박자표가 곡의 박자표(첫 마디, 못갖춘마디면 그 다음)와 다른 마디는 못갖춘마디가 아니고 곡 격자 마디(`grid.cells * grid.slotTicks`)보다 짧고 길이가 칸 길이(`grid.slotTicks`)의 정수배일 때만 변환한다. 그 마디는 원래 내용 뒤의 모자란 칸을 빈칸 `_`로 채우고([마디 길이와 빈칸](#가져오기-규칙) 행), 마디 메모(변환기 근사 메모 쪽)에 `원본 2/4 마디`를 단다. 도돌이·이동으로 펼친 사본마다 같다. 격자보다 길거나 칸 길이의 정수배가 아닌 마디가 있으면 그 마디 번호와 박자를 담은 이유로 변환하지 않는다. 4/4 곡이 4칸 격자에 맞지 않는 리듬을 가지면(옮긴 음 `?`가 하나라도 생기면) `Math.round(4분음표 템포 * 2)`가 `BPM_MAX` 이하일 때 8칸(8분음표 칸)으로 다시 변환해 보고 옮긴 음 수가 4칸보다 적으면 8칸 결과를 쓴다. 이때 설명 열에 `8칸(8분음표 칸): 4칸으로는 맞지 않는 리듬이 있음`을 한 번 붙이고 BPM은 위 환산(8분음표 칸은 ×2)을 따른다. 4/4가 아닌 박자는 바꾸지 않는다 |
| BPM | alphaTab 첫 템포(4분음표 기준)를 한 칸 길이로 환산한다(8분음표 칸은 ×2, 점4분음표 칸은 ×2/3). 반올림해서 30~240으로 자르고, 잘랐으면 설명 열에 `BPM 자름(원래 값 n)`. 곡 중간 템포 변화는 따라가지 않고 그 마디 메모 `템포 변화 생략` |
| 마디 길이와 빈칸 | 마디의 실제 길이는 그 마디 내용(모든 성부 중 가장 긴 것)의 길이다. 격자 마디보다 모자란 길이 중 칸 길이(`grid.slotTicks`)의 정수배는 빈칸 `_` 칸으로 채운다. 못갖춘마디(`isAnacrusis`)는 마디 앞쪽에, 박자표가 바뀐 짧은 마디와 곡의 마지막 마디는 뒤쪽에 둔다. 칸보다 작은 나머지는 그 칸 안의 쉼 `r`로 채운다(2/4 곡 4분음표 칸에서 16분음표 둘짜리 못갖춘마디 → `_ r/r/음/음`, 나머지가 생기는 칸은 빈칸 묶음과 소리 칸 사이에 있다). 박자표가 바뀐 마디는 그 박자표의 길이를 실제 길이로 보고, 곡의 마지막 마디(연주 순서의 마지막)는 내용이 격자 마디보다 짧을 때만 내용의 길이를 쓴다. 그 밖의 마디에서 내용이 모자란 자리는 지금처럼 쉼 `r`이나 유지 `-`다. 빈칸 칸은 음·쉼 판정, 성부 합치기, 길이가 다른 음 겹침, 8칸 자동 선택(옮긴 음 수)에 들어가지 않는다. 변환 결과의 빈칸은 `GuitarParser.validateScore`의 빈칸 규칙(마디 앞쪽 또는 뒤쪽 묶음 하나, 마디 전체 빈칸 금지)을 지킨다. 마지막 마디가 비어 있으면(내용 길이 0) 빈칸으로 채우지 않고 쉼으로 둔다 |
| 시작 자리 | 모든 음의 시작(틱)을 칸 격자에 놓는다. 칸마다 그 칸 안 시작 자리와 쉼이 시작하는 자리가 칸을 d(1·2·3·4)로 나눈 자리에 모두 맞는 가장 작은 d를 고른다(오차는 `TOLERANCE_TICKS`). 쉼 시작 자리는 칸 안에서 음이 끝났는데 그 뒤로 울리는 음이 하나도 없는 자리다(다른 성부, 붙임줄로 이어진 음, 앞 마디에서 이어진 음 포함. 다른 음이 계속 울리면 넣지 않는다). 쉼 시작 자리까지 맞는 d가 없으면 쉼 시작 자리는 버리고 시작 자리만으로 고른다. 그래도 맞는 d가 없으면 오차 합이 가장 작은 d(같으면 4)로 옮기고, 옮긴 음에 `?`, 그 마디 메모 `칸 분할에 맞지 않는 리듬 → 가까운 자리`. 마디 길이를 넘는 음은 빼고 `마디 길이를 넘는 음 생략` |
| 성부 | 트랙의 모든 성부를 합친다. 같은 자리에 시작하는 음은 `+` 화음. 한 조각(같은 칸·같은 분할 자리)에 같은 줄(줄 없는 음이면 같은 음높이)·같은 음높이의 음이 둘 이상이면 끝이 가장 늦은 하나만 남기고, 남긴 것에 왼손·오른손 운지·주법이 비어 있으면 버린 것에서 가져온다(두 성부가 같은 순간 같은 음을 쳐도 `C3@5+C3@5`가 되지 않는다). 한 마디의 박 글(`txt`)도 같은 글은 한 번만 쓴다. 조각에 새로 시작하는 음이 없으면 앞 음이 울리는 중일 때 `-`, 아니면 `r`(`r` 바로 뒤나 곡 맨 앞에는 `-`를 두지 않는다). 붙임줄 도착 음은 다시 치지 않는 음이라 새 시작으로 보지 않는다. 성부가 둘 이상이고 길이가 다른 음이 겹치면 한 마디라도 그러면 설명 열에 `긴 음은 시작만 적음`을 한 번만 적는다(마디 메모에는 달지 않는다). 빈칸 칸은 이 판정에 들어가지 않고, 앞 음의 유지 사슬은 빈칸을 건너 이어진다 |
| 음 | 줄과 프렛에서 `개방현 + 프렛`(카포는 넣지 않는다. 우리 문법은 카포 없는 음높이). 토큰은 `[주법][왼손][음이름][옥타브]@줄[:오른손]`, 음이름은 `#`(조표 무시). alphaTab `note.string`은 가장 낮은 줄이 1이라 우리 줄 번호는 `줄 수 - string + 1`. 줄 정보 없는 음(`note.string`이 1보다 작은 음. 음이름으로 적은 음이 이 꼴이다)은 `note.realValue`(이조 반영)의 음높이만 쓰고 `@줄`은 붙이지 않는다(앱이 기본 위치를 고른다). 트랙 전체에 줄이 없는 경우(조율이 없는 MusicXML 오선 파트, 음이름으로만 적은 alphaTex)와 6줄 트랙 안의 음 하나가 줄이 없는 경우가 같은 코드 하나를 쓴다. 한 화음 안에 줄 있는 음과 없는 음이 섞여도 되고 줄 있는 음만 `@줄`을 붙인다. 음역(6번 줄 개방 ~ 1번 줄 `GuitarNotation.MAX_FRET` 프렛) 밖의 음은 옥타브를 옮겨 안에 넣고 `?` + 마디 메모 `음역 밖 → 옥타브 옮김`. 줄이 있어야 하는 주법(슬라이드 `g`, 하모닉스 `h`, `{slur}` 짝이 아닌 슬러)은 빼고 종류별로 마디 메모 `줄 정보 없음: 슬러 생략`·`줄 정보 없음: 슬라이드 생략`·`줄 정보 없음: 하모닉스 생략`. 롤·화음·운지는 그대로이고, 트랙 전체에 줄이 없으면 설명 열에 `줄 정보 없음(기본 위치)` |
| 주법 | 해머링·풀링 도착 음에 `s`(alphaTex `{slur 이름}` 짝의 도착 음도 같다. 줄 없는 음도 출발 음과 음높이가 다르면 `s`이고, 같은 높이 짝은 주법도 메모도 없다. 줄 없는 음의 `s`가 앱의 기본 줄 판정(`parser.validateScore`)에서 `INVALID_SLUR`가 되면 그 마디의 그 `s`만 빼고 `줄 정보 없음: 슬러 생략`. 줄 있는 음은 출발 음과 같은 줄일 때만 `s`이고 다른 줄이면 빼고 `다른 줄 슬러 생략`), 슬라이드(legato·shift) 도착 음에 `g`(출발 음과 같은 줄이 아니면 주법 없이 `슬라이드 생략`). 자연 하모닉스는 `h` + 울리는 음(`GuitarNotation.NATURAL_HARMONICS`)과 `@줄`이고, 표에 없는 프렛이면 보통 음 + `하모닉스 프렛 아님`, 인공 하모닉스는 보통 음 + `인공 하모닉스 → 보통 음`. arpeggio down(낮은 줄 → 높은 줄)은 박 하나가 아니라 같은 자리에서 합친 조각의 음이 둘 이상일 때 `~`(두 성부가 음 하나씩 가진 롤도 `~`), arpeggio up은 `~` + `위에서 아래 롤 → 아래에서 위`, brush·strum은 동시에 + `스트로크 → 동시에`. 꾸밈음은 빼고 `꾸밈음 생략`, 데드 노트는 빼고 `데드 노트 생략`. 벤딩·비브라토·트레몰로·위미바·트릴은 음만 적고 마디마다 한 번 종류를 메모. 왼손 운지는 alphaTab 검지~소지를 1~4로(엄지·모름은 없음), 오른손은 엄지·검지·중지·약지를 `:p :i :m :a`로. [변환 규칙](#변환-규칙)의 표를 거꾸로 읽은 것이다 |
| 코드 이름 | 마디 안 첫 코드 이름을 `[이름]`. 코드가 없는 마디는 연주 순서에서 바로 앞 마디 끝에 울리던 코드(그 마디 코드를 시작 순으로 정렬한 마지막 항목, 코드가 없었으면 그 마디가 이어 받은 코드)를 `[이름]`으로 이어 적고 메모는 달지 않는다. 곡의 첫 코드 전 마디와 이어 받은 이름이 우리 문법이 받지 않는 이름이면 `[-]`(메모 없음). 폭 없는 글자(`GuitarAlphaTex.CHORD_NAME_PAD`)는 뗀다. 우리 문법이 받지 않는 이름(`INVALID_CHORD`)은 `[-]` + `코드 이름 변환 불가: 이름`. 마디 안에서 코드가 더 바뀌면 메모에 `n박부터 이름` 코드 사전에 없는 이름(`UNSUPPORTED_CHORD`)이면 괄호를 벗긴 이름(`F7(b5)`→`F7b5`), `7(9)` 꼴이면 `9`로 바꾼 이름(`Am7(9)`→`Am9`) 순으로 사전에 있는 첫 이름을 머리표에 쓰고 그 마디 메모에 `원본 F7(b5)`를 단다(모두 없으면 원래 이름). 이어 적은 마디는 바꾼 이름을 잇고 `원본` 메모를 달지 않으며, 마디 안에서 바뀌는 코드 메모는 원래 이름이다. |
| 도돌이 | 도돌이표와 1·2번 괄호는 alphaTab의 연주 순서(`MidiFileGenerator`가 만드는 `tickLookup.masterBars`)대로 펼치고, 펼친 도돌이 구간의 첫 마디에 메모 `도돌이 펼침`. D.S.·D.C.·To Coda 같은 이동 표시(alphaTex `\jump 이름`)도 같은 재생 순서가 따라가서 펼쳐진다. 이동 표시가 붙은 마디 다음에 순서대로가 아닌 마디가 오고 그 마디가 그 이동의 도착지(D.S.류는 세뇨 표지 마디, D.C.류는 첫 마디, To Coda는 코다 표지 마디)일 때만, 그 마디(이동해서 들어온 첫 마디)의 메모에 `표시 이름 펼침`(예: `D.S. al Coda 펼침`, `D.C. al Fine 펼침`, `To Coda 펼침`)을 단다. Fine에서 끝나는 것은 메모가 없다. 1·2번 괄호로 건너뛴 자리에는 이동 메모를 달지 않고, 괄호의 첫 마디에 `1번 괄호`·`2번 괄호`(`alternateEndings`)를 단다. D.S.·D.C. 가 적힌 마디의 박 글(`txt`)에 `with Repeat`(대소문자 무시)가 있으면 그 이동 뒤 구간은 도돌이와 1·2번 괄호를 첫 바퀴처럼 다시 지키고, To Coda·Fine은 그 구간의 마지막 바퀴에서만 따른다(alphaTab의 순서는 이동 뒤 도돌이를 건너뛰므로 이때만 변환기가 순서를 따로 셈한다. 글이 없으면 alphaTab 순서 그대로다) 못갖춘마디(`isAnacrusis`)는 앞쪽을 빈칸 `_`로 채우고(마디 길이와 빈칸 행) 메모 `못갖춘마디` |
| 제목·설명 | 제목은 `score.title`(없으면 파일 이름), 탭·줄바꿈·줄 바꿈 없는 공백은 한 칸 공백으로. 설명은 `원본: 파일 이름 · alphaTab 변환` 뒤에 `Capo n`, `BPM 자름`, 곡 전체 성부 메모. 머리 `notices`가 있으면 설명은 notices 그대로(탭·줄바꿈만 공백으로)이고 그 뒤에 곡 전체 근사 메모(`BPM 자름`, `줄 정보 없음(기본 위치)`, 곡 전체 `긴 음은 시작만 적음`)만 ` · `로 붙는다. 이때 `Capo n`은 notices가 이미 카포 표기(`getSongCapo`가 읽는 꼴)를 갖거나 제목에 있으면 붙이지 않고, `capo n`이 있는데 표기가 없으면 설명 끝에 ` · Capo n`을 붙인다(앱은 카포를 제목·설명 표기로만 읽는다) |
| 마디 메모 | 박의 글(`txt`)이 그 마디 메모가 된다. 한 마디에 여럿이면 시간 순서로 ` · `로 잇고, 변환기가 만드는 근사 메모는 그 뒤에 ` · `로 붙는다 |
| 섹션(리허설 기호) | 마디의 `section`(alphaTex `\section ("A")`)의 마커와 글을 공백으로 이은 글이 그 마디 메모의 맨 앞이다(박의 글보다 앞). 도돌이·이동으로 펼친 사본마다 같다 |
| 페르마타 | 박에 `fermata`가 있으면 그 마디 메모 `페르마타`(변환기 근사 메모 쪽). 길이는 늘리지 않는다 |

### 하지 못하는 것

- 이동 표시는 alphaTab이 연주 순서에 넣는 것만 펼친다(`with Repeat` 글이 있는 첫 D.S.·D.C. 하나만 예외로 변환기가 이동 뒤 순서를 셈한다. 그런 이동이 둘 이상이거나 이동 뒤 구간 안에 또 다른 이동이 있는 곡은 안 돌려 봤다).
- 표에 없는 박자(5/4, 7/8 등)와 6줄 표준 조율이 아닌 곡은 변환하지 않는다. 곡 중간 박자 변경은 격자보다 짧고 칸 길이의 정수배인 마디만 받고(가져오기 규칙의 칸 행) 격자보다 길거나 정수배가 아닌 마디가 있으면 변환하지 않는다. 첫 마디가 못갖춘마디 표시 없이 다른 박자표(1/4 등)인 곡은 그 박자가 곡의 박자표가 되어 표에 없는 박자로 거절된다.
- 다른 악기 트랙(베이스 등 4줄·5줄 현악기, 드럼)은 고르지 않는다. 6줄 기타도 줄 정보 없는 음높이 트랙도 없으면 변환하지 않는다. 줄 정보가 없는 트랙은 어느 악기인지 알 수 없어서 피아노 파트도 음높이만 있으면 고른다.
- 줄 정보 없는 음(줄 정보 없는 트랙의 모든 음, 6줄 트랙 안의 줄 없는 음)은 `@줄` 없이 앱이 기본 위치를 고르게 하므로 원본 운지(어느 줄에서 치는지)는 사라지고, 그 음에 걸린 슬러·슬라이드·하모닉스는 빠진다.
- alphaTex로는 한 보표에 `프렛.줄` 음과 음이름 음을 섞어 적을 수 없다(alphaTab이 오류 AT218로 읽지 못한다). 6줄 트랙 안의 줄 없는 음은 Guitar Pro·MusicXML을 읽은 모델에서만 나온다.
- 트랙의 첫 6줄 보표(또는 음높이가 있는 첫 보표) 하나만 읽는다. 압축 MusicXML(`.mxl`)은 받지 않는다.
- 곡 중간 템포 변화는 첫 템포만 쓰고 그 마디 메모만 남긴다.

## 사진 변환

사진(교본 악보)은 AI가 alphaTex로 옮기고, 우리 악보는 그 alphaTex에서 변환기가 만든다.

```text
앱 곡 선택 바의 `변환 프롬프트 복사` (src/score-prompt.js 의 buildScoreImagePrompt)
  → AI 채팅에 사진과 함께 붙여 넣기 → alphaTex 코드블록
  → 드라이브 GuitarScores/곡.tex 로 저장
  → PC에서 node tools/build-scores.js <폴더>   (곡.tsv, 6열)
  → Apps Script → 시트 → 앱
```

- 2026-10-20 결정: 사진에서 우리 문법으로 바로 옮기던 길(옛 `변환 프롬프트`가 TSV 한 행을 내던 것)을 없앴다. 사진 → alphaTex → 우리 악보 한 길만 둔다. 이유는 둘이다. 첫째, 책에 적힌 정보(성부, 실제 음 길이, 도돌이, D.S., 못갖춘마디)를 AI가 우리 문법에 맞게 줄이다 잃는데, alphaTex에는 그대로 적을 수 있다. 둘째, 우리 문법이나 변환기가 좋아지면 원본 alphaTex에서 변환기만 다시 돌려 정보를 다시 꺼낸다. 프롬프트는 우리 문법이 아니라 alphaTex를 가르친다. 우리 문법 표(`Docs/score-format.md`)는 변환기와 사람이 읽는 용이다.
- 저장소를 열어 둔 코딩 AI에게는 `프로젝트 프롬프트 복사`(`buildProjectPrompt`)를 쓴다. AI가 같은 변환 규칙(`buildScoreImagePrompt()`)을 따라 `Temp/scores/<제목>.tex`를 저장하고 `node tools/build-scores.js Temp/scores`로 `<제목>.tsv`(6열)를 만들며, 오류가 있으면 `.tex`를 고쳐 오류 0이 되게 한다. `Temp/scores`는 구글 드라이브와 이어진 폴더라 그 안의 다른 파일은 건드리지 않게 한다.
- 프롬프트가 요구하는 것: alphaTex 코드블록 하나만(설명 없음), 머리(`\title` `\notices` `\tempo (n)` `\ts` `\displaytranspose 12`(음이름 곡) `\capo` `\tuning`), 마디(`|`, 도돌이는 펼치지 않고 `\ro` `\rc n` `\ae n`, 못갖춘마디 `\ac`, 곡 중간 박자표 변경은 그 마디 첫 음 앞의 `\ts (2 4)`와 다음 마디의 원래 `\ts (4 4)`(쉼으로 채우지 않음), 리허설 기호 `\section ("A")`, 이동 표시 `\jump 이름`, 세뇨 표지나 D.S.·D.C. 옆에 (with Repeat)가 있으면 D.S.·D.C. 마디 박에 `{txt "with Repeat"}`(세뇨 옆에 인쇄돼도 D.S. 마디에), al Coda·al Fine이 인쇄되지 않아도 To Coda와 코다 표지가 있으면 `dalsegnoalcoda`·`dacapoalcoda`, Fine이 있으면 `dalsegnoalfine`·`dacapoalfine`), 음(줄을 알면 `프렛.줄`, 오선만 있으면 `C4`로 한 옥타브 빼고, 줄을 추측하지 않음), 길이·묶음(`.길이`, `{d}` `{tu 3}` `{t}`, `\voice` 두 성부), 주법(`{h}` `{sl}`(음이름 곡은 해머링·풀링을 `{slur s1}` 짝으로, 슬라이드는 `{txt "슬라이드"}`만) `{nh}` `{ad}` `{au}`(롤 물결선이 두 성부에 걸치면 두 성부의 그 박에 모두) `{gr}` `{fermata medium}`, 운지 `{lf 2}`~`{lf 5}` `{rf 1}`~`{rf 4}`, 코드 이름 `{ch "Am"}`), 메모(`{txt "…"}`, 확인은 `{txt "확인: 이유"}`, 아포얀도는 옮기지 않음).
- 표기는 vendor 파서(`vendor/alphatab/dist/alphaTab.core.mjs`)와 Node에서 읽어 확인한 것만 넣었다. 두 성부가 여러 마디에 걸칠 때는 `\voice` 다음에 첫째 성부의 모든 마디를 `|`로 이어 쓰고, 다시 `\voice` 다음에 둘째 성부의 모든 마디를 쓴다. 마디 표시는 첫째 성부에만 둔다. 음이름 음의 운지는 음 효과 `C4{lf 2 rf 2}.4`로 읽힌다(박 효과 `C4.4 {lf 2}`는 읽히지 않는다).
- 2026-10-20 결정: 프롬프트는 한 곡에 `프렛.줄` 음과 음이름 음을 섞지 말라고 한다. alphaTab은 한 보표에 두 방식이 섞이면 오류로 읽지 못한다(위 함정). TAB이 없는 마디가 섞인 곡은 곡 전체를 음이름으로 적게 한다. 줄을 추측하지 않는 원칙은 그대로다.
- 2026-10-20 결정: 섹션은 `\section ("A")`로 적게 한다. 괄호 없는 `\section "A"`는 뒤따르는 음이름을 둘째 인자로 읽어 실패한다(명령줄 도구 절의 결정).
- `test/test-score-prompt.js`는 프롬프트의 예시 코드블록(`ALPHATEX_EXAMPLES`)이 vendor alphaTab에서 진단 0으로 읽히고 `tools/alphatab-to-score.js`로 바꾼 결과가 `validateScore` 오류 0인지, 규칙 속 짧은 alphaTex 조각과 이동 표시 이름이 모두 읽히는지, 규칙 문장이 빠지지 않았는지 확인한다. 일부러 어긋난 사본(예시의 이동 표시 이름 오타, 닫히지 않은 중괄호, 규칙 조각의 없는 효과, 지운 규칙 행)이 걸리는지도 본다.
- 2026-10-20 확인: 친구를 찾아서(교본 2쪽, 36마디, 두 성부, D.S. with Repeat)를 이 프롬프트대로 손으로 alphaTex로 옮겨 기존 시트 악보(58마디)와 견줬다. 펼친 마디 수와 49마디의 칸이 같았다. 다른 9마디 중 2마디(D/C 두 번)는 기존 시트가 붙임줄을 잘못 읽은 것이었다. 이 교본은 TAB의 붙임줄 곡선을 이어지는 음의 한 줄 위에 그린다. 나머지는 하모닉스 표기(`h`), 화음 안 음 순서, Bb를 A#로 적는 변환기 규칙, 인쇄되지 않은 코드 이름, Am7(9) 코드 이름 차이였다. 이 과정에서 프롬프트를 글자 그대로 따르면 틀리는 곳 셋(세뇨 옆 with Repeat, al Coda 없는 D.S., 두 성부 롤)을 찾아 규칙을 더했다.
- 안 돌려 본 것: 실제 AI가 이 프롬프트로 만든 alphaTex의 품질(오선 옥타브 읽기, 두 성부 나누기)과 PC에서 `build-scores.js`를 거쳐 시트로 가는 전체 길.
