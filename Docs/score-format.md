# 악보 문법

내장곡, Google Sheets, 임시 악보 초안이 함께 쓰는 텍스트 악보 문법이야. 이 문서는 문법만 다뤄. 사용 흐름은 [사용 안내](usage.md), 재생 계약은 [리듬·오디오 계약](beginner-rhythm.md), 화면 표시는 [화면과 조작](ui.md)에 있어.

파싱·검증 기준은 `src/notation.js`(마디·칸 구조)와 `src/parser.js`(음·코드 토큰), `src/rhythm.js`(유지 체인)야. 사진 변환 프롬프트(`src/score-prompt.js`)는 이 문법을 앱을 모르는 AI용으로 옮긴 거라, 문법을 바꾸면 프롬프트도 같이 고쳐.

## 곡과 마디

곡은 마디의 나열이야. 마디는 줄바꿈이나 `//`로 나눠. 마디 한 줄의 모양은 이래.

```text
[코드] 칸 칸 ... 칸 | "메모"
```

| 부분 | 규칙 |
|---|---|
| `[코드]` | 코드 이름(`[Am]`, `[G7]`, `[C/G]` 등). `[-]`는 코드 없음. 비우거나(`[]`) 생략하거나 `[?]`로 두면 앱이 코드를 추론해. `[C?]`처럼 이름 뒤 `?`는 추론된 코드라는 표시야. 원문에 코드가 없다는 걸 남기려면 `[-]`를 써 |
| 칸 | 공백으로 구분해. 한 곡의 모든 마디는 칸 수가 같아야 해([박자, 칸, BPM](#박자-칸-bpm)) |
| `\| "메모"` | JSON 문자열 하나. 운지·포지션·연습 메모·가사를 적고, 없으면 `""`이나 생략. 문자열 안의 `/`와 `//`는 마디 구분이 아니야. 따옴표 없이 적거나 JSON이 깨지면 `INVALID_LYRIC_QUOTE` 오류야 |

코드 이름은 대문자 A~G로 시작하는 영문 코드 표기여야 해(`src/parser.js` `validateScore`의 정규식). 아니면 `INVALID_CHORD` 오류야. 영문 표기면 코드 사전(`CHORD_DB`)에 없어도 받아. 코드 카드를 못 그릴 뿐이고 `UNSUPPORTED_CHORD` 경고만 나와.

## 칸

한 칸에는 아래 다섯 가지 중 하나가 들어가.

| 칸 내용 | 뜻 | 예 |
|---|---|---|
| 음 토큰 | 그 칸이 시작할 때 그 음을 쳐 | `E4`, `1C4@2:i` |
| 화음 | 음 토큰 2개 이상을 공백 없이 `+`로 묶어 동시에 쳐 | `E2@6+B3@2+G4@1` |
| `r` | 쉼. 그 순간 기타 직접음을 모두 정리해(콘서트홀 잔향은 남을 수 있어) | `r` |
| `-` | 유지. 바로 앞의 음이나 화음 전체를 다시 치지 않고 이어. 마디를 넘어갈 수 있어 | `-` |
| 분할 | 위 네 가지를 공백 없이 `/`로 2·3·4개 이어 칸을 균등하게 나눠 | `E4/F4`, `C4/-/-/D4`, `E2@6+E4@1/G4` |

- `-`는 곡 맨 앞이나 쉼 바로 뒤(분할 안의 `r/-` 포함)에 올 수 없어(`ORPHAN_HOLD`).
- 한 화음 안에 `@`로 같은 줄을 두 번 지정하면 `STRING_COLLISION` 오류야. `@` 없이 기본 위치끼리 겹치면 `DEFAULT_STRING_COLLISION` 경고만 나와.
- `.`은 쉼인지 유지인지 모호해서 오류야(`AMBIGUOUS_REST_TOKEN`).

## 음 토큰

음 토큰은 아래 자리를 이 순서로 붙여 써. 꼭 있어야 하는 건 음이름과 옥타브고, 나머지는 원문에 있을 때만 붙여.

```text
[주법][왼손 손가락][음이름][변화표][옥타브][@줄 번호][:오른손 손가락][?]
```

| 자리 | 값 | 뜻 |
|---|---|---|
| 주법 | `!` 아포얀도, `~` 티란도 | 재생 gain에 반영돼. 화음에서는 그 구성음에만 적용되고 다른 구성음에 전파하지 않아 |
| 왼손 손가락 | `0`~`4` | 표시용. 적힌 것만 보여 주고 추정하지 않아 |
| 음이름 | `C D E F G A B` | 대문자만 |
| 변화표 | `#`, `b` | 실제 음높이를 반음 바꿔. 겹올림·겹내림은 없어 |
| 옥타브 | `2`~`5` | 가운데 도가 C4야 |
| 줄 번호 | `@1`~`@6` | 칠 줄을 정해. 생략하면 앱이 기본 위치를 골라(`src/parser.js`의 `FIRST_POS`, `midiInfo`) |
| 오른손 손가락 | `:p` 엄지, `:i` 검지, `:m` 중지, `:a` 약지 | 표시용. 음색·gain·타이밍·피치를 바꾸지 않아 |
| 확인 표시 | `?` | [확인 표시](#확인-표시) |

예: `!1C4@2:i?`는 아포얀도, 왼손 1번, C4, 2번 줄, 오른손 검지, 확인 필요야. 화음은 구성음마다 자기 운지를 붙여(`C3@5:p+1C4@2:i`). 분할 조각도 마찬가지야(`E4:i/F4:m/-`).

`>`와 `^`는 아포얀도 별칭이 아니고 오류야. `!`로 적어. 음 뒤 길이 접미사(`*2`)는 없어. 2026-10-19에 뺀 이유는 [리듬·오디오 계약](beginner-rhythm.md)에 있어.

### 받지 않는 옛 표기

옥타브 생략(`E`), 소문자 음이름(`e4`), `♯`·`♭`·`♮`, 뒤에 붙인 주법(`E4!`), 괄호 왼손 운지(`D4(4)`), 한글 계이름(`도4`, `0솔`), 괄호 묶음(`(E4 F4)`), 쉼표 분할(`E4,F4`), 따옴표 없는 메모(`| 0시 0시`), 대문자 쉼 `R`, 코드 별칭(`[없음]`, `[N.C.]`, `[자동]`, `(추정)`)은 모두 오류야. 같은 뜻은 위의 표기로 적어(`4D4`, `!E4`, `E4/F4`, `| "메모"`, `r`, `[-]`, `[?]`).

2026-10-19 결정: 예전 악보를 읽으려고 남겨 둔 표기였는데, 앱은 한 사람이 쓰고 옮길 옛 악보가 없어. 같은 뜻의 표기가 여럿이면 사람과 AI가 헷갈리고 검증만 느슨해져서 모두 지웠어. 코드 별칭만 지우면 `[없음]`이 "없음"이라는 코드 이름으로 통과해서, 코드 이름을 영문 표기로 제한하는 `INVALID_CHORD`를 같이 넣었어.

## 음높이

- 음높이는 실제로 울리는 소리야. 카포가 있으면 카포가 없는 것처럼 적고, 앱이 재생할 때 카포만큼 올려([시트 한 행과 카포](#시트-한-행과-카포)).
- 표준 튜닝 개방현은 1번 줄 E4, 2번 줄 B3, 3번 줄 G3, 4번 줄 D3, 5번 줄 A2, 6번 줄 E2야. 기타 오선보는 실음보다 한 옥타브 높게 적으니 오선에서 읽은 옥타브 숫자에서 1을 빼.
- 조표와 앞선 임시표는 적용하지 않아. 토큰마다 실제 음높이를 적어.
- 음역은 E2~E5(0~12프렛)야. 벗어나면 `GUITAR_RANGE` 오류야. `@줄`을 붙인 음은 그 줄 개방현부터 12반음 위까지만 되고, 아니면 `INVALID_STRING_OVERRIDE` 오류야.

## 박자, 칸, BPM

칸 하나가 메트로놈 클릭 한 번이고, BPM은 분당 칸 수야. 화면과 시트에서 고르는 마디 칸 수는 2, 3, 4, 6, 8, 9야. 칸 길이 해석은 `GuitarRhythm.getGridInfo`가 정해.

| 칸 수 | 박자 | 한 칸 |
|---|---|---|
| 2, 3, 4 | 2/4, 3/4, 4/4 | 4분음표 |
| 6, 9 | 6/8, 9/8 | 8분음표 |
| 8 | 4/4 | 8분음표 |

- 인쇄된 템포의 음표 단위가 칸과 다르면 환산해. BPM = 인쇄 템포 × (템포 음표 길이 ÷ 한 칸 길이). 4분음표=60을 8칸으로 적으면 120, 점4분음표=60을 6칸으로 적으면 180이야.
- 3/4의 셋잇단은 3칸을 고르고 그 칸을 3분할해. 9칸을 3/4 셋잇단으로 쓰지 마.
- 12/8이나 빠른 6/8·9/8은 4칸·2칸·3칸을 고르고 각 칸을 3분할해 점4분음표 칸처럼 쓸 수 있어. 재생 길이는 맞지만 박자 카드의 음표 이름은 4분음표 칸 기준으로 보여.
- 앱이 받는 BPM은 30~240이야. 시트는 1 이상의 정수를 받고, 범위를 벗어난 값은 곡을 열 때 앱이 30~240으로 잘라.

## 음 길이

음은 시작하는 칸이나 분할 조각에 적고, 남은 길이는 `-`로 채워. 길이는 칸 단위고, 마디의 나머지 칸은 생략했어.

| 표기 | 길이(칸) | 한 칸이 4분음표일 때 | 한 칸이 8분음표일 때 | 한 칸이 점4분음표일 때 |
|---|---|---|---|---|
| `E4` | 1 | 4분음표 | 8분음표 | 점4분음표 |
| `E4 -` | 2 | 2분음표 | 4분음표 | 점2분음표 |
| `E4 - -` | 3 | 점2분음표 | 점4분음표 |  |
| `E4 - - -` | 4 | 온음표 | 2분음표 | 점온음표 |
| `E4/F4` | 1/2 + 1/2 | 8분음표 둘 | 16분음표 둘 |  |
| `r/E4` | 쉼 1/2 + 1/2 | 8분쉼표 + 8분음표 | 16분쉼표 + 16분음표 |  |
| `E4 -/F4` | 3/2 + 1/2 | 점4분음표 + 8분음표 | 점8분음표 + 16분음표 |  |
| `E4/F4/G4/A4` | 1/4 × 4 | 16분음표 넷 | 32분음표 넷 |  |
| `E4/-/F4/G4` | 1/2 + 1/4 + 1/4 | 8분음표 + 16분음표 둘 | 16분음표 + 32분음표 둘 |  |
| `E4/F4/G4/-` | 1/4 + 1/4 + 1/2 | 16분음표 둘 + 8분음표 | 32분음표 둘 + 16분음표 |  |
| `E4/-/-/F4` | 3/4 + 1/4 | 점8분음표 + 16분음표 | 점16분음표 + 32분음표 |  |
| `E4/F4/G4` | 1/3 × 3 | 8분음표 셋잇단 | 16분음표 셋잇단 | 8분음표 셋 |
| `E4/-/F4` | 2/3 + 1/3 | 셋잇단 4분음표 + 8분음표 | 셋잇단 8분음표 + 16분음표 | 4분음표 + 8분음표 |
| `E4/F4/-` | 1/3 + 2/3 | 셋잇단 8분음표 + 4분음표 | 셋잇단 16분음표 + 8분음표 | 8분음표 + 4분음표 |
| `E4/F4 -/G4` | 1/2 + 1 + 1/2 | 당김음 8분-4분-8분 | 당김음 16분-8분-16분 |  |

이 표의 원본은 `src/score-prompt.js`의 `RHYTHM_EXAMPLES`이고, `test/test-score-prompt.js`가 각 표기를 파서로 읽어 길이가 맞는지 확인해. 표를 다시 뽑는 명령:

```powershell
node -e "var q = String.fromCharCode(96); require('./src/score-prompt.js').RHYTHM_EXAMPLES.forEach(function(e){ console.log('| ' + q + e.notation + q + ' | ' + [e.lengthText, e.quarter, e.eighth, e.dottedQuarter].join(' | ') + ' |'); })"
```

- 붙임줄은 길이를 더한 한 음이야(뒤쪽은 `-`).
- 화음 구성음은 같은 길이를 가져. 구성음마다 길이를 나누거나 성부마다 쉼을 둘 수 없어. 길이가 다른 성부는 시작 칸에 `+`로 합치고 그 뒤 칸에는 새로 시작하는 음만 적어. 다른 줄의 음은 자연 감쇠로 이어져.
- 악보 음가와 기타 소리의 자연 여운은 별개야. 소리가 정리되는 경계는 [리듬·오디오 계약](beginner-rhythm.md)에 있어.

## 확인 표시

칸이나 분할 조각, 화음 구성음 끝에 `?`를 하나 붙이면 확인이 필요하다는 표시야. 예: `E4?`, `1C4@2:i?`, `C3@5+E4@1?`, `E4?/F4`.

- `?`를 뗀 음을 그대로 파싱·재생해. 음높이·현·운지·리듬은 `?`가 없을 때와 같아.
- `r?`, 단독 `?`는 확인 표시가 붙은 쉼이야. 쉼 판별은 `GuitarNotation.isRestToken` 하나로 해.
- `??`, `-?`, `.?`는 오류야.
- 원문 `tok`에 `?`가 남아서 악보 복사(TSV)와 초안에도 그대로 남아. 확인을 마치면 마디 편집에서 지워.
- 코드 머리표의 `[?]`, `[C?]`는 코드 추론 표시라 이것과 상관없어.
- 화면 표시(경고색 칸, `확인 N곳` 배지)는 [화면과 조작](ui.md)의 확인 표시에 있어.

2026-10-19 결정: AI로 사진을 변환할 때 읽지 못한 음을 오류로 막으면 시트 전체가 안 들어오고 사용자가 AI를 여러 번 다시 돌리게 돼. 불러오기는 통과시키고 위치만 눈에 띄게 해서 앱에서 직접 고치게 했어.

## 시트 한 행과 카포

Google Sheets의 한 행이 곡 하나야. `src/sheets.js`가 읽어.

| A | B | C | D | E |
|---|---|---|---|---|
| 제목 | 칸 수(2, 3, 4, 6, 8, 9) | BPM(1 이상의 정수) | 설명 | 악보 |

- A열이 비었거나 `곡 제목`, `제목`, `title`이면 그 행은 건너뛰어.
- B열이 `[`로 시작하거나 `|`가 있으면 옛 2열 형식으로 보고, B열부터를 악보로 읽어(칸 수 4, BPM 64).
- 악보 칸 안에서는 마디를 ` // `로 이어 써. 칸 안의 줄바꿈도 마디 구분이야.
- 제목이나 설명에 `Capo 2`, `카포: 2`처럼 적으면 그 카포(0~12)를 써. 없으면 저장된 카포 값을 써. 표시 프렛은 카포 기준이고, 재생 실음에만 오프셋을 한 번 더해.
- 한 행이라도 오류가 있으면 시트 전체를 불러오지 않고, 곡 선택 바 아래에 첫 오류를 보여 줘.

## 오류와 경고

오류가 있는 악보는 불러오기, 초안 편집 적용, TSV 복사, 재생이 막혀. 경고는 막지 않아.

| 코드 | 종류 | 뜻 |
|---|---|---|
| `EMPTY_SCORE` | 오류 | 악보가 비어 있어 |
| `EMPTY_MEASURE` | 오류 | `//` 사이나 끝에 빈 마디가 있어 |
| `INVALID_BEATS` | 오류 | 칸 수가 1~12의 정수가 아니야 |
| `TOO_MANY_BEATS`, `MISSING_BEATS` | 오류 | 마디 칸 수가 남거나 모자라. 빈 칸을 자동으로 채우지 않아 |
| `ISOLATED_SLASH` | 오류 | 공백으로 떨어진 `/` |
| `EMPTY_SUBDIVISION` | 오류 | 분할이나 화음 안에 빈 조각이 있어 |
| `UNSUPPORTED_SUBDIVISION` | 오류 | 2·3·4 이외의 분할 |
| `UNBALANCED_DELIMITER` | 오류 | 괄호, 대괄호, 따옴표가 닫히지 않았어 |
| `INVALID_LYRIC_QUOTE` | 오류 | 메모가 큰따옴표 JSON 문자열이 아니거나 깨졌어 |
| `INVALID_CHORD` | 오류 | 코드 이름이 대문자 A~G로 시작하는 영문 코드 표기가 아니야 |
| `AMBIGUOUS_REST_TOKEN` | 오류 | `.` |
| `ORPHAN_HOLD` | 오류 | 곡 맨 앞이나 쉼 뒤의 `-` |
| `UNKNOWN_NOTE` | 오류 | 읽을 수 없는 음 토큰 |
| `GUITAR_RANGE` | 오류 | E2~E5 밖의 음 |
| `INVALID_STRING_OVERRIDE` | 오류 | 그 줄에서 0~12프렛으로 칠 수 없는 `@줄` |
| `STRING_COLLISION` | 오류 | 한 화음에서 `@`로 같은 줄을 두 번 지정 |
| `DEFAULT_STRING_COLLISION` | 경고 | 기본 위치끼리 같은 줄에서 겹쳐 |
| `UNSUPPORTED_CHORD` | 경고 | 코드 사전에 없는 코드 이름 |

## 지원하지 않는 것

독립 성부별 길이와 쉼, 화음 일부의 붙임줄, 슬러·꾸밈음 표기, 못갖춘마디, 곡 중간의 박자 변경, 반복 기호 자동 전개, 변칙 조율은 문법에 없어. 반복은 펼쳐 적고, 그 밖에는 이미지 악보 모드로 연습해. 사진 변환 프롬프트는 이런 표기를 가볍게 편곡해 이 문법으로 옮기고 마디 메모에 적게 해([개발 안내](development.md)의 사진 변환 프롬프트).
