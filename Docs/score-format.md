# 악보 문법

내장곡, Google Sheets, 임시 악보 초안, 악보 입력 화면이 함께 쓰는 텍스트 악보 문법이다. 이 문서는 문법만 다룬다. 사용 흐름은 [사용 안내](usage.md), 재생 계약은 [리듬·오디오 계약](beginner-rhythm.md), 화면 표시는 [화면과 조작](ui.md)에 있다.

파싱·검증 기준은 `src/notation.js`(마디·칸 구조)와 `src/parser.js`(음·코드 토큰), `src/rhythm.js`(유지 체인)다. 사진 변환 프롬프트(`src/score-prompt.js`)는 2026-10-20부터 이 문법이 아니라 alphaTex를 가르친다([alphaTab 보기](alphatab.md#사진-변환)). 이 문서의 문법과 표는 변환기(`tools/alphatab-to-score.js`)가 내는 결과와 사람이 읽는 용이다.

## 곡과 마디

곡은 마디의 나열이다. 마디는 줄바꿈이나 `//`로 나눈다. 마디 한 줄의 모양은 이렇다.

```text
[코드] 칸 칸 ... 칸 | "메모"
```

| 부분 | 규칙 |
|---|---|
| `[코드]` | 코드 이름(`[Am]`, `[G7]`, `[C/G]` 등). `[-]`는 코드 없음. 비우거나(`[]`) 생략하거나 `[?]`로 두면 앱이 코드를 추론한다. `[C?]`처럼 이름 뒤 `?`는 추론된 코드라는 표시다. 원문에 코드가 없다는 것을 남기려면 `[-]`를 쓴다 |
| 칸 | 공백으로 구분한다. 한 곡의 모든 마디는 칸 수가 같아야 한다([박자, 칸, BPM](#박자-칸-bpm)) |
| `\| "메모"` | JSON 문자열 하나. 운지·포지션·연습 메모·가사를 적고, 없으면 `""`이나 생략. 문자열 안의 `/`와 `//`는 마디 구분이 아니다. 따옴표 없이 적거나 JSON이 깨지면 `INVALID_LYRIC_QUOTE` 오류다 |

코드 이름은 대문자 A~G로 시작하는 영문 코드 표기여야 한다(`src/parser.js` `validateScore`의 정규식). 아니면 `INVALID_CHORD` 오류다. 영문 표기면 코드 사전(`CHORD_DB`)에 없어도 받는다. 코드 카드를 못 그릴 뿐이고 `UNSUPPORTED_CHORD` 경고만 나온다.

## 칸

한 칸에는 아래 다섯 가지 중 하나가 들어간다.

| 칸 내용 | 뜻 | 예 |
|---|---|---|
| 음 토큰 | 그 칸이 시작할 때 그 음을 친다 | `E4`, `1C4@2:i` |
| 화음 | 음 토큰 2개 이상을 공백 없이 `+`로 묶어 동시에 친다 | `E2@6+B3@2+G4@1` |
| `r` | 쉼. 그 순간 기타 직접음을 모두 정리한다(콘서트홀 잔향은 남을 수 있다) | `r` |
| `-` | 유지. 바로 앞의 음이나 화음 전체를 다시 치지 않고 잇는다. 마디를 넘어갈 수 있다 | `-` |
| 분할 | 위 네 가지를 공백 없이 `/`로 2·3·4개 이어 칸을 균등하게 나눈다 | `E4/F4`, `C4/-/-/D4`, `E2@6+E4@1/G4` |

- `-`는 곡 맨 앞이나 쉼 바로 뒤(분할 안의 `r/-` 포함)에 올 수 없다(`ORPHAN_HOLD`).
- 한 화음 안에 `@`로 같은 줄을 두 번 지정하면 `STRING_COLLISION` 오류다. `@` 없이 기본 위치끼리 겹치면 `DEFAULT_STRING_COLLISION` 경고만 나온다.
- `.`은 쉼인지 유지인지 모호해서 오류다(`AMBIGUOUS_REST_TOKEN`).

## 음 토큰

음 토큰은 아래 자리를 이 순서로 붙여 쓴다. 꼭 있어야 하는 것은 음이름과 옥타브고, 나머지는 원문에 있을 때만 붙인다.

```text
[주법][왼손 손가락][음이름][변화표][옥타브][@줄 번호][:오른손 손가락][?]
```

| 자리 | 값 | 뜻 |
|---|---|---|
| 주법 | `!` 아포얀도, `h` 자연 하모닉스, `s` 슬러, `g` 슬라이드 | `!`는 재생 gain에 반영된다. 화음에서는 그 구성음에만 적용되고 다른 구성음에 전파하지 않는다. 표시가 없는 음은 티란도로 친다. `!`·`h`·`s`·`g`는 한 음에 하나만 온다. 하모닉스는 [하모닉스](#하모닉스), 슬러는 [슬러](#슬러), 슬라이드는 [슬라이드](#슬라이드) 절 |
| 왼손 손가락 | `0`~`4` | 표시용. 적힌 것만 보여 주고 추정하지 않는다 |
| 음이름 | `C D E F G A B` | 대문자만 |
| 변화표 | `#`, `b` | 실제 음높이를 반음 바꾼다. 겹올림·겹내림은 없다 |
| 옥타브 | `2`~`5` | 가운데 도가 C4다. 6을 적으면 음역 밖이라 `GUITAR_RANGE` 오류다(하모닉스는 예외) |
| 줄 번호 | `@1`~`@6` | 칠 줄을 정한다. 생략하면 앱이 기본 위치를 고른다(`src/parser.js`의 `FIRST_POS`, `midiInfo`) |
| 오른손 손가락 | `:p` 엄지, `:i` 검지, `:m` 중지, `:a` 약지 | 표시용. 음색·gain·타이밍·피치를 바꾸지 않는다 |
| 확인 표시 | `?` | [확인 표시](#확인-표시) |

예: `!1C4@2:i?`는 아포얀도, 왼손 1번, C4, 2번 줄, 오른손 검지, 확인 필요다. 화음은 구성음마다 자기 운지를 붙인다(`C3@5:p+1C4@2:i`). 분할 조각도 마찬가지다(`E4:i/F4:m/-`). 조각 맨 앞의 `~`는 롤이다([롤](#롤)).

`>`와 `^`는 아포얀도 별칭이 아니고 오류다. `!`로 적는다. 음 뒤 길이 접미사(`*2`)는 없다. 2026-10-19에 뺀 이유는 [리듬·오디오 계약](beginner-rhythm.md)에 있다.

### 받지 않는 옛 표기

옥타브 생략(`E`), 소문자 음이름(`e4`), `♯`·`♭`·`♮`, 뒤에 붙인 주법(`E4!`), 괄호 왼손 운지(`D4(4)`), 한글 계이름(`도4`, `0솔`), 괄호 묶음(`(E4 F4)`), 쉼표 분할(`E4,F4`), 따옴표 없는 메모(`| 0시 0시`), 대문자 쉼 `R`, 코드 별칭(`[없음]`, `[N.C.]`, `[자동]`, `(추정)`)는 모두 오류다. 같은 뜻은 위의 표기로 적는다(`4D4`, `!E4`, `E4/F4`, `| "메모"`, `r`, `[-]`, `[?]`).

2026-10-19 결정: 티란도 표시 `~`를 없앴다. 따로 적지 않은 음은 티란도로 치니 아포얀도만 표시하면 되고, `~`는 입력만 번거로웠다. 전에는 `~` 음을 표시 없는 음보다 작게 재생했는데, 이제 표시 없는 음과 같은 소리다. 내장 로망스 1부 두 판에서 `~`를 지웠다. 2026-10-20에 `~`를 롤 기호로 다시 썼다([롤](#롤)).

2026-10-19 결정: 예전 악보를 읽으려고 남겨 둔 표기였는데, 앱은 혼자 쓰는 용도이고 옮길 옛 악보가 없다. 같은 뜻의 표기가 여럿이면 사람과 AI가 헷갈리고 검증만 느슨해져서 모두 지웠다. 코드 별칭만 지우면 `[없음]`이 "없음"이라는 코드 이름으로 통과해서, 코드 이름을 영문 표기로 제한하는 `INVALID_CHORD`를 같이 넣었다.

## 음높이

- 음높이는 실제로 울리는 소리다. 카포가 있으면 카포가 없는 것처럼 적고, 앱이 재생할 때 카포만큼 올린다([시트 한 행과 카포](#시트-한-행과-카포)).
- 표준 튜닝 개방현은 1번 줄 E4, 2번 줄 B3, 3번 줄 G3, 4번 줄 D3, 5번 줄 A2, 6번 줄 E2다. 기타 오선보는 실음보다 한 옥타브 높게 적으니 오선에서 읽은 옥타브 숫자에서 1을 뺀다.
- 조표와 앞선 임시표는 적용하지 않는다. 토큰마다 실제 음높이를 적는다.
- 음역은 E2~B5(0~19프렛)다. 벗어나면 `GUITAR_RANGE` 오류다. `@줄`을 붙인 음은 그 줄 개방현부터 19반음 위까지만 되고, 아니면 `INVALID_STRING_OVERRIDE` 오류다. 범위는 `GuitarNotation.MAX_FRET` 하나가 정한다.

2026-10-20 결정: 음역을 0~12프렛(E2~E5)에서 클래식 기타 표준인 19프렛(B5)까지 넓혔다. 12는 첫 버전부터 지판 그림(1~12프렛)과 함께 정한 값이었고 이유를 적은 기록은 없었다. 교본 곡의 13프렛 음과 하모닉스 음(예: 7프렛 하모닉스 F#5)을 옥타브를 내리지 않고 적으려는 것이다. 이보다 높은 하모닉스(E6 등)는 여전히 받지 않는다. 내장곡을 MIDI에서 만드는 `tools/midi-to-score.js`의 줄 고르기(`fixStringCollisions`)도 같은 상수를 읽는다. 이 함수는 겹친 음을 바로 아래 줄 하나로만 옮길 수 있고(아래 줄일수록 프렛이 커져서), 한도를 넘으면 "풀지 못한 충돌"로 남긴다. 그래서 한도를 넓혀 바뀌는 것은 전에 못 풀던 충돌뿐이다. 내장곡 27곡을 `songs.json` 그대로 12와 19로 다시 돌려 보니 못 푼 충돌이 0건이고 결과가 같았다. 앞으로 변환하는 곡에서는 전에 사람에게 넘기던 충돌을 13~19프렛으로 자동 배정할 수 있다.

## 박자, 칸, BPM

칸 하나가 메트로놈 클릭 한 번이고, BPM은 분당 칸 수다. 화면과 시트에서 고르는 마디 칸 수는 2, 3, 4, 6, 8, 9다. 칸 길이 해석은 `GuitarRhythm.getGridInfo`가 정한다.

| 칸 수 | 박자 | 한 칸 |
|---|---|---|
| 2, 3, 4 | 2/4, 3/4, 4/4 | 4분음표 |
| 6, 9 | 6/8, 9/8 | 8분음표 |
| 8 | 4/4 | 8분음표 |

- 인쇄된 템포의 음표 단위가 칸과 다르면 환산한다. BPM = 인쇄 템포 × (템포 음표 길이 ÷ 한 칸 길이). 4분음표=60을 8칸으로 적으면 120, 점4분음표=60을 6칸으로 적으면 180이다.
- 3/4의 셋잇단은 3칸을 고르고 그 칸을 3분할한다. 9칸을 3/4 셋잇단으로 쓰지 않는다.
- 12/8이나 빠른 6/8·9/8은 4칸·2칸·3칸을 고르고 각 칸을 3분할해 점4분음표 칸처럼 쓸 수 있다. 재생 길이는 맞지만 박자 카드의 음표 이름은 4분음표 칸 기준으로 보인다.
- 앱이 받는 BPM은 30~240이다. 시트는 1 이상의 정수를 받고, 범위를 벗어난 값은 곡을 열 때 앱이 30~240으로 자른다.

## 음 길이

음은 시작하는 칸이나 분할 조각에 적고, 남은 길이는 `-`로 채운다. 길이는 칸 단위고, 마디의 나머지 칸은 생략했다.

| 표기 | 길이(칸) | 한 칸이 4분음표일 때 | 한 칸이 8분음표일 때 | 한 칸이 점4분음표일 때 |
|---|---|---|---|---|
| `E4` | 1 | 4분음표 | 8분음표 | 점4분음표 |
| `E4 -` | 2 | 2분음표 | 4분음표 | 점2분음표 |
| `E4 - -` | 3 | 점2분음표 | 점4분음표 |  |
| `E4 - - -` | 4 | 온음표 | 2분음표 | 점온음표 |
| `E4/F4` | 1/2 + 1/2 | 8분음표 둘 | 16분음표 둘 |  |
| `r/E4` | 쉼 1/2 + 1/2 | 8분쉼표 + 8분음표 | 16분쉼표 + 16분음표 |  |
| `E4 -/F4` | 3/2 + 1/2 | 점4분음표 + 8분음표 | 점8분음표 + 16분음표 |  |
| `E4/F4/G4/A4` | 1/4 × 4 | 16분음표 넷 | 32분음표 넷 |  |
| `E4/-/F4/G4` | 1/2 + 1/4 + 1/4 | 8분음표 + 16분음표 둘 | 16분음표 + 32분음표 둘 |  |
| `E4/F4/G4/-` | 1/4 + 1/4 + 1/2 | 16분음표 둘 + 8분음표 | 32분음표 둘 + 16분음표 |  |
| `E4/-/-/F4` | 3/4 + 1/4 | 점8분음표 + 16분음표 | 점16분음표 + 32분음표 |  |
| `E4/F4/G4` | 1/3 × 3 | 8분음표 셋잇단 | 16분음표 셋잇단 | 8분음표 셋 |
| `E4/-/F4` | 2/3 + 1/3 | 셋잇단 4분음표 + 8분음표 | 셋잇단 8분음표 + 16분음표 | 4분음표 + 8분음표 |
| `E4/F4/-` | 1/3 + 2/3 | 셋잇단 8분음표 + 4분음표 | 셋잇단 16분음표 + 8분음표 | 8분음표 + 4분음표 |
| `E4/F4 -/G4` | 1/2 + 1 + 1/2 | 당김음 8분-4분-8분 | 당김음 16분-8분-16분 |  |

이 표의 원본은 `src/score-prompt.js`의 `RHYTHM_EXAMPLES`이고, `test/test-score-prompt.js`가 각 표기를 파서로 읽어 길이가 맞는지 확인한다. 표를 다시 뽑는 명령:

```powershell
node -e "var q = String.fromCharCode(96); require('./src/score-prompt.js').RHYTHM_EXAMPLES.forEach(function(e){ console.log('| ' + q + e.notation + q + ' | ' + [e.lengthText, e.quarter, e.eighth, e.dottedQuarter].join(' | ') + ' |'); })"
```

- 붙임줄은 길이를 더한 한 음이다(뒤쪽은 `-`).
- 화음 구성음은 같은 길이를 가진다. 구성음마다 길이를 나누거나 성부마다 쉼을 둘 수 없다. 길이가 다른 성부는 시작 칸에 `+`로 합치고 그 뒤 칸에는 새로 시작하는 음만 적는다. 다른 줄의 음은 자연 감쇠로 이어진다.
- 악보 음가와 기타 소리의 자연 여운은 별개다. 소리가 정리되는 경계는 [리듬·오디오 계약](beginner-rhythm.md)에 있다.

## 하모닉스

음 토큰의 주법 자리에 `h`를 붙이고, **실제로 울리는 음높이**와 `@줄`을 적는다. 예: B줄(2번 줄) 7프렛 하모닉스는 `hF#5@2`다. 개방 B3보다 한 옥타브와 완전5도 위의 F#5가 울리기 때문이다.

- 자연 하모닉스만 받는다. 손 대는 프렛과 울리는 음의 관계는 `GuitarNotation.NATURAL_HARMONICS`가 정한다(손 대는 프렛 → 개방현에서 울리는 음까지 반음 수). 적힌 음이 그 줄 개방현에서 표의 반음 수만큼 위가 아니면 `INVALID_HARMONIC` 오류다.
- `@줄`이 꼭 있어야 한다. 없으면 어느 줄의 하모닉스인지 알 수 없어서 `INVALID_HARMONIC` 오류다.
- 음역 제한(`GuitarNotation.MAX_FRET`)을 받지 않는다. 그래서 옥타브 6도 되고(예: 1번 줄 4프렛 하모닉스), 일반 음으로는 칠 수 없는 높이도 적을 수 있다. 같은 줄 충돌 검사는 손 대는 프렛으로 한다.
- `!`와 같이 못 쓴다(`!h…`, `h!…`는 오류). 화음에서는 구성음마다 따로 붙인다(`E2@6+hE5@1`). 왼손·오른손 운지와 `?`는 다른 음처럼 붙는다(`h1…`은 `[주법][왼손]` 순서).
- 연습 화면의 TAB은 손 대는 프렛을 `<7>`처럼 보이고, 지판의 목표 마커는 손 대는 자리에 마름모로 그린다. 오선은 손 대는 자리의 음에 마름모 머리로 그린다([오선 미리보기](staff-notation.md)).
- 재생은 적힌 실제 음높이(`midi`)로 하고 음색·gain은 보통 음과 같다.
- 인공 하모닉스는 없다. 변환기(`tools/alphatab-to-score.js`)도 그 밖의 하모닉스는 실제 음높이의 보통 음으로 바꾼다.

2026-10-20 결정: 자연 하모닉스를 문법에 넣었다(1단계). 손 대는 자리와 울리는 음이 달라서, TAB을 교본에 맞추면 소리가 틀리고 소리를 맞추면 TAB이 틀렸다(자나르칸드 인트로). 그래서 적는 음은 울리는 음이고 손 대는 프렛은 표에서 구한다. 오선을 손 대는 자리로 그리는 것은 실제 음으로 그리면 1번 줄 4프렛의 G#6이 그림 높이를 넘어서기 때문이다. 악보 입력 화면은 2단계에서 주법 줄에 `<>` 하모닉스 단추를 뒀고, 하모닉스가 든 악보를 받아 내보내는 것도 된다([악보 입력](tab-input.md)). `H` 키로도 켜고 끄며, 오선 모드에서는 누른 자리를 손 대는 자리로 보고 줄을 옮겨 켠다([오선 입력](staff-input.md)).

## 슬러

슬러(리가도: 해머링·풀링)로 이어지는 **뒤 음**, 곧 오른손으로 다시 치지 않는 음의 주법 자리에 `s`를 붙인다. 예: `E4/sF4`는 E4를 치고 F4는 왼손으로 눌러 잇는다.

- 해머링과 풀링은 따로 적지 않는다. 앞 음보다 높으면 해머링(`hammer`), 낮으면 풀링(`pull`)이다. 방향은 파싱 결과의 `slurType`에 실린다.
- 앞 음은 **같은 줄에서 마지막으로 친 음**이다. 사이에 `-`(유지)나 마디 줄이 있어도 되고, 쉼(`r`)이 있으면 안 된다. 곡 처음이나 쉼 뒤의 슬러, 같은 줄에서 친 음이 없는 슬러는 `INVALID_SLUR` 오류다. 규칙은 `GuitarNotation.linkSlurs` 한 곳에만 있고 검사(`validateScore`)·파싱 결과(`parseScore`)·악보 입력 화면이 같이 쓴다.
- 앞 음과 같은 높이면 `INVALID_SLUR` 오류다. 같은 음을 잇는 붙임줄은 슬러가 아니라 `-`로 적는다.
- `@줄`이 없는 슬러 음은 앱이 고른 기본 줄로 판정한다. 앞 음과 줄이 다르게 잡히면 오류가 나니 `@줄`을 붙인다(`E4@2/sF4@2`).
- 화음 안에서는 구성음마다 따로 붙고(`E2@6+sF4@1`), 그 구성음만 앞 조각의 같은 줄 음과 견준다. `!`·`h`와 같이 못 쓴다(`!s…`, `hs…`는 오류).
- 소리는 보통 음과 높이·길이가 같고 gain만 작다(`src/guide.js`의 `SLUR_GAIN`). 음색은 그대로다.
- 연습 화면 TAB은 프렛 숫자 앞에 방향 글자를 붙인다: 해머링은 `h7`, 풀링은 `p5`(`.fret-slur`). 오선에는 곡선으로 그린다([오선 미리보기](staff-notation.md#슬러-곡선)). 악보 입력 화면은 입력판 `⌒ 슬러` 단추와 `S` 키로 넣는다([악보 입력](tab-input.md), [오선 입력](staff-input.md)).
- 슬라이드는 같은 잇기 규칙에 `g`를 쓴다([슬라이드](#슬라이드)).

2026-10-20 결정: 슬러를 문법에 넣었다(1단계). 교본 곡마다 슬러가 많은데 "슬러 → 따로 침"으로 옮기면 모든 음을 다시 쳐서 리가도 연습이 안 됐다. 뒤 음에 `s`를 붙이면 높낮이로 해머링과 풀링이 정해져서 방향을 따로 적을 필요가 없고, 같은 줄 규칙을 검사가 지켜서 TAB에서 어긋난 슬러를 바로 잡는다. 1단계는 표기·검사·연습 화면의 소리와 TAB·입력 화면의 표시와 왕복·사진 변환 프롬프트까지고, 오선 곡선(2단계)과 입력 단추·키(3단계)는 뒤로 미뤘다.

## 롤

화음 앞에 세로 물결선이 있으면 그 조각 맨 앞에 `~`를 붙인다. 예: `~E2@6+B3@2+G4@1`. 분할 안에서는 그 조각에만 걸린다(`C3@5/~A3@3+D4@2+F#4@1`).

- `+`로 묶은 두 음 이상 화음의 맨 앞에만 온다. 단음(`~E4`), 쉼(`~r`), 유지(`~-`), 화음 가운데(`E2+~B3`), 두 번(`~~…`)은 `INVALID_ROLL` 오류다.
- 방향은 낮은 줄에서 높은 줄로(6번 줄 → 1번 줄) 하나뿐이다.
- 구성음의 `!`·`h`·`s`, 운지, `?`는 롤과 따로 붙는다(`~E2@6:p+hE5@1`).
- 소리는 첫 음(가장 큰 번호 줄)이 박에 맞고, 나머지는 줄 번호가 작아지는 순서로 조금씩 늦게 친다. 간격과 상한은 `src/guide.js`의 `ROLL_STEP`·`ROLL_MAX_SHARE`이고, 조각이 짧으면 간격을 줄인다([리듬·오디오 계약](beginner-rhythm.md)).
- 연습 화면 TAB은 화음 왼쪽에 세로 물결선(`.roll-mark`)을 그리고, 오선도 머리 왼쪽에 물결선을 그린다([오선 미리보기](staff-notation.md#롤-물결선)). 악보 입력 화면은 카드 TAB에도 물결선을 그리고, 입력판 `⌇ 롤` 단추와 `` ` `` 키로 켜고 끈다([악보 입력](tab-input.md)).

2026-10-20 결정: 롤을 문법에 넣었다(1단계). 클래식 곡에서 자주 나오는데 "롤 → 동시에"로 옮기면 화음을 한 번에 쳐서 소리가 달랐다. 기호는 물결선 모양인 `~`로 골랐다. 2026-10-19에 없앤 티란도 표시였지만 그것을 쓰던 내장 로망스에서는 이미 지웠고 시트 곡에는 없어서, 새 뜻으로 써도 헷갈릴 악보가 없었다. 아래로 굴리는 롤은 클래식 기타에서 드물어 뺐다. 첫 음을 박에 맞춘 것은 베이스가 메트로놈 박과 같이 들리게 하려는 것이다.

## 슬라이드

같은 줄에서 손가락을 미끄러뜨려 닿는 **뒤 음**의 주법 자리에 `g`를 붙인다. 예: `E3@4/gF#3@4`는 E3를 치고 F#3까지 미끄러진다. 책의 S(슬라이드, 곡선과 함께)와 두 음 사이 직선의 gliss.(글리산도)를 모두 `g`로 적는다.

- 앞 음을 정하는 규칙은 슬러와 같다(`GuitarNotation.linkSlurs`): 같은 줄에서 마지막으로 친 음이고, 사이 `-`와 마디 줄은 되지만 쉼은 안 된다. 곡 처음·쉼 뒤·같은 줄 음 없음·같은 높이는 `INVALID_SLIDE` 오류다.
- 방향은 앞 음보다 높으면 `up`, 낮으면 `down`이다(파싱 결과의 `slideType`, 출발 음 높이는 `slideFromMidi`).
- `!`·`h`·`s`와 같이 못 쓴다. 화음 안에서는 구성음마다 따로 붙는다.
- 소리: 오른손으로 다시 치지 않는 음이라 gain은 슬러와 같은 `SLUR_GAIN`이고, 출발 음 높이에서 시작해 짧게 제 높이로 미끄러진다(`src/guide.js`의 `SLIDE_GLIDE_SEC`·`SLIDE_MAX_SHARE`, [리듬·오디오 계약](beginner-rhythm.md)).
- 연습 화면 TAB은 프렛 앞에 방향을 붙인다: 올라가면 `/7`, 내려가면 `\5`(`.fret-slide`). 판정이 틀어진 슬라이드는 `—7`이다. 악보 입력 화면은 슬라이드가 든 악보를 받아 내보내고 카드 TAB에 같은 글자를 보여 준다. 오선에는 두 머리를 잇는 직선으로 그린다([오선 미리보기](staff-notation.md#슬라이드-직선)). 악보 입력 화면은 입력판 `/ 슬라이드` 단추와 `/` 키로 넣는다([악보 입력](tab-input.md), [오선 입력](staff-input.md)).
- 출발 음이 없는 글리산도(음 앞뒤의 짧은 사선·곡선)는 받지 않는다. 변환기도 빼고 메모에 남긴다(alphaTex 프롬프트는 그 박에 `{txt "글리산도 생략"}`을 달게 한다).

2026-10-20 결정: 슬라이드·글리산도를 문법에 넣었다(1단계). 교본 곡에서 "슬라이드 → 따로 침"으로 옮기면 뒤 음을 다시 쳐서 소리가 달랐다. 책의 S와 gliss.는 뒤 음을 다시 치느냐가 다르지만 가이드음에서는 차이가 작아서 `g` 하나로 합쳤다. 기호는 슬러(`s`)처럼 뒤 음 앞에 붙이는 글자로 골랐고, glide·glissando의 g다. 출발 음이 없는 글리산도는 시작 높이를 정할 수 없어 뺐다.

## 확인 표시

칸이나 분할 조각, 화음 구성음 끝에 `?`를 하나 붙이면 확인이 필요하다는 표시다. 예: `E4?`, `1C4@2:i?`, `C3@5+E4@1?`, `E4?/F4`.

- `?`를 뗀 음을 그대로 파싱·재생한다. 음높이·현·운지·리듬은 `?`가 없을 때와 같다.
- `r?`, 단독 `?`는 확인 표시가 붙은 쉼이다. 쉼 판별은 `GuitarNotation.isRestToken` 하나로 한다.
- `??`, `-?`, `.?`는 오류다.
- 원문 `tok`에 `?`가 남아서 악보 복사(TSV)와 초안에도 그대로 남는다. 확인을 마치면 마디 편집에서 지운다.
- 코드 머리표의 `[?]`, `[C?]`는 코드 추론 표시라 이것과 상관없다.
- 화면 표시(경고색 칸, `확인 N곳` 배지)는 [화면과 조작](ui.md)의 확인 표시에 있다.

2026-10-19 결정: AI로 사진을 변환할 때 읽지 못한 음을 오류로 막으면 시트 전체가 안 들어오고 사용자가 AI를 여러 번 다시 돌리게 된다. 불러오기는 통과시키고 위치만 눈에 띄게 해서 앱에서 직접 고치게 했다.

## 시트 한 행과 카포

Google Sheets의 한 행이 곡 하나다. `src/sheets.js`가 읽는다.

| A | B | C | D | E |
|---|---|---|---|---|
| 제목 | 칸 수(2, 3, 4, 6, 8, 9) | BPM(1 이상의 정수) | 설명 | 악보 |

- F열(선택)은 곡의 원본 alphaTex다. 있으면 alphaTab 보기 창이 이 alphaTex를 그대로 읽어 그린다. 앱은 악보를 E열에서만 읽고 F열은 악보로 읽지 않는다. 흐름과 만드는 법은 [alphaTab 보기](alphatab.md#원본은-alphatex)에 있다.
- A열이 비었거나 `곡 제목`, `제목`, `title`이면 그 행은 건너뛴다.
- B열이 `[`로 시작하거나 `|`가 있으면 옛 2열 형식으로 보고, B열부터를 악보로 읽는다(칸 수 4, BPM 64).
- 악보 칸 안에서는 마디를 ` // `로 이어 쓴다. 칸 안의 줄바꿈도 마디 구분이다.
- 제목이나 설명에 `Capo 2`, `카포: 2`처럼 적으면 그 카포(0~12)를 쓴다. 둘 다 있으면 제목 것이다. 표기가 없으면 곡 객체의 `capo` 값을 쓰는데, 이 값도 곡을 만들 때 같은 표기에서 읽은 것이라 결국 표기가 카포를 정한다. 표시 프렛은 카포 기준이고, 재생 실음에만 오프셋을 한 번 더한다.
- 한 행이라도 오류가 있으면 시트 전체를 불러오지 않고, 곡 선택 바 아래에 첫 오류를 보여 준다.

## 지원하지 않는 것

독립 성부별 길이와 쉼, 화음 일부의 붙임줄, 출발 음이 없는 글리산도·꾸밈음 표기, 못갖춘마디, 곡 중간의 박자 변경, 반복 기호 자동 전개, 변칙 조율은 문법에 없다. 반복은 펼쳐 적고, 그 밖에는 이미지 악보 모드로 연습한다. 사진 변환은 alphaTex로 책의 표기를 그대로 적고, 변환기가 이런 표기를 가볍게 근사하거나 펼쳐 이 문법으로 옮기며 마디 메모에 남긴다([alphaTab 보기](alphatab.md#사진-변환)).
