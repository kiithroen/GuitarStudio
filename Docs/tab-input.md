# 악보 입력 (타브)

`score-input.html`은 타브를 마우스와 키보드로 찍어 텍스트 악보로 바꾸는 별도 페이지야. 오선보를 보고 음높이와 음표 길이로 넣는 방식은 [오선 입력](staff-input.md)에 따로 있어(같은 문서에 써). 연습 화면 곡 선택 바의 `악보 입력`으로 들어가. 문법은 [악보 문법](score-format.md), 연습 화면의 임시 악보는 [개발 안내](development.md)의 초안과 저장을 봐.

2026-10-19 결정: 사진 변환은 저작권이 끝났거나 이용 허락이 있는 악보만 AI에 맡길 수 있어. 그 밖의 악보는 사용자가 직접 입력해야 하는데, 텍스트 문법을 손으로 치면 느리고 틀리기 쉬워. 그래서 줄과 프렛을 고르면 문법에 맞는 텍스트가 나오는 입력 화면을 따로 만들었어. 연습 화면 안에 넣지 않은 건 연습 화면이 이미 기능이 많고, 입력은 긴 시간 한 곡에 집중하는 작업이라 화면을 통째로 쓰는 게 낫기 때문이야.

## 화면

위에서 아래로 이렇게 놓여. 칸 너비는 `max(48px, 나눈 수 × 조각 폭)`이고 조각 폭은 그 칸 프렛 글자(운지·주법 포함)의 실제 폭 + 6px, 최소 26px이야. 2026-10-19 결정: 처음에는 조각 폭을 26px로 고정했는데, `!7(4)a`처럼 운지가 붙은 글자가 넘쳐 데스크톱에서도 카드마다 가로 스크롤바가 생겼어.

| 영역 | 내용 |
|---|---|
| 헤더 | 제목 `악보 입력`, `연습 화면으로` 링크 |
| 곡 정보 | 제목, 칸 수(2·3·4·6·8·9), BPM(30~240), 설명, 조표(조표 없음은 `♯로 적기`·`♭으로 적기`), `새 악보`, `불러오기`, `되돌리기`, `다시 하기`, 자동 저장 상태 |
| 선택 막대 | 마디를 고르면 나타나. `복사`, `붙여넣기`, `복제`, `비우기`, `삭제`, `뒤에 빈 마디`, `선택 해제` |
| 마디 카드 | 마디마다 하나. 머리(마디 번호, 코드 칸), 칸 머리(칸 번호와 나눈 수), 오선 미리보기([오선 미리보기](staff-notation.md)), 6줄 타브, 메모 칸, 변환된 한 줄. 카드들이 든 영역(`#tiMeasures`)은 자체 스크롤이야(아래) |
| `+ 마디 추가` | 마지막 카드 뒤 |
| 결과 | 검사 결과(오류·경고), 변환된 악보 전체(읽기 전용), `악보 텍스트 복사`, `시트용 TSV 복사`, `연습 화면에서 열기` |
| 입력판 | 화면 아래에 붙어 있어. 지금 위치, 6줄×13프렛(0~12) 지판, 칸 버튼, 운지 버튼. 접을 수 있어 |

마디 영역 높이는 화면 높이에서 입력판·선택 막대 높이와 여백 32px를 뺀 만큼까지(최소 280px)이고, 넘치면 그 안에서 스크롤해. 영역 끝까지 굴리면 페이지가 이어서 내려가 결과가 나와. 2026-10-19 결정: 처음에는 카드가 페이지 길이대로 늘어나서 곡이 길면 결과(`연습 화면에서 열기`·TSV 복사)를 보려고 한참 내려가야 했어. 영역 높이를 묶어 페이지 길이가 곡 길이와 상관없게 했어.

타브는 위가 1번 줄이야(인쇄 타브와 같아). 4분할 칸도 두 자리 프렛을 누를 수 있게 조각 폭을 최소 26px로 둬(칸 너비 규칙은 위).

## 입력 방법

### 위치 고르기

- 타브의 한 자리(조각 × 줄)를 누르면 커서가 거기로 가. 음이 있는 자리면 그 음을 들려줘.
- 커서는 조각 하나와 줄 하나야. 조각은 나눈 칸의 한 토막이고, 나누지 않은 칸은 조각이 하나야.
- 오른쪽 클릭은 커서를 그 자리로 옮기고 음을 지워.
- 키보드·`◀ ▶`·자동 이동으로 커서가 움직이면 커서 조각이 입력판에 가리지 않게 스크롤해. 먼저 마디 영역 안을 굴려 조각을 보이게 하고(조각 여백 8px), 그다음 페이지를 굴려 마디 영역 전체가 선택 막대와 입력판 사이에 들어오게 해(영역의 `scroll-margin`). 마우스로 고른 자리는 이미 보이니 스크롤하지 않아.

### 입력판 지판

- `s`번 줄 `f`프렛을 누르면 커서 조각의 `s`번 줄에 `f`프렛을 넣고 커서 줄을 `s`로 옮겨. 그 줄에 음이 있었으면 바꿔(운지는 지워져). 조각이 쉼이었으면 쉼을 풀어.
- 이미 그 프렛이 들어 있는 자리를 다시 누르면 지워.
- 지판 칸에는 그 자리의 음이름을 작게 적어. 변화표 설정(`♯`/`♭`)을 따라.
- 커서 조각에 든 음은 지판에서 칠해 보여 주고, 커서 줄은 옅게 칠해.
- 한 조각에 여러 줄을 넣으면 화음이야. 한 줄에는 한 음만 들어가.

### 입력판 버튼

| 버튼 | 동작 |
|---|---|
| `◀` `▶` | 앞·뒤 조각으로 |
| `쉼표` | 조각을 쉼으로 바꾸고 음을 지워. 쉼이면 풀어 |
| `칸 비우기` | 조각의 음과 쉼을 지워 빈 조각으로 |
| `나누기 1·2·3·4` | 커서가 있는 칸을 그 수로 균등하게 나눠 |
| `들어보기` | 커서 조각의 음을 한꺼번에 들려줘 |
| `입력 시 자동 이동` | 켜면 음을 넣은 뒤 커서가 다음 조각으로 가. 기본은 꺼짐 |
| `소리` | 입력·클릭 때 들려주기. 기본은 켜짐 |
| `입력판 접기` | 지판과 운지 줄을 숨겨 |

`입력 시 자동 이동`을 켜면 선율은 지판만 눌러 한 음에 한 번씩 입력해. 기본을 끈 건 화음을 넣을 때 첫 음에서 커서가 넘어가 버리기 때문이야. 음을 넣었을 때만 넘어가고, 지판으로 음을 지웠을 때는 그대로 있어. 켠 상태에서 마지막 마디의 마지막 조각 다음으로 넘어가면 빈 마디를 하나 붙여(음 넣기와 같은 되돌리기 한 단계). 방향키로는 붙이지 않아.

지판은 같은 프렛을 다시 누르면 지우는 토글이고, 숫자키는 늘 넣기만 해(같은 프렛이면 바뀌는 것 없이 소리와 이동만). 마우스로 누른 버튼은 누른 뒤 포커스를 풀어서 Space가 그 버튼을 다시 누르지 않고 들어보기가 되게 해.

2026-10-19 결정: 입력판이 악보를 덜 가리게 높이를 줄였어. 처음 판은 1024×768에서 입력판이 270px쯤이라 마디가 한 줄 반밖에 안 보였고, 휴대폰에서는 화면의 반 넘게 덮었어. 폭 640px 이상에서는 운지 버튼들을 지판 오른쪽 세로 열에 두고 안내는 그 열 아래에 작게 적어(폭 900px 미만에서는 안내를 숨겨). 운지 줄을 지판 아래 한 줄로 두면 안내와 합쳐 1024px 폭을 넘어 두 줄로 접혔기 때문이야. 폭 640px 미만에서는 첫 줄을 가로 스크롤 한 줄로 두고, 운지 줄은 `운지` 버튼(`#tiAttrsToggle`)으로 펼쳐. 곡 정보도 640px 이상에서는 두 줄로 모았어. 높이 목표는 브라우저 스모크가 확인해(1024×768 입력판 210px·곡 정보 150px 이하, 375×812 입력판 325px 이하).

### 운지와 표시

커서 자리에 음이 있으면 입력판 운지 줄로 그 음에 붙일 수 있어. 문법의 음 토큰 자리와 같아.

| 줄 | 버튼 |
|---|---|
| 왼손 | 없음, 0, 1, 2, 3, 4 |
| 오른손 | 없음, p, i, m, a |
| 주법 | 없음, `!` 아포얀도 |
| 확인 | `?` 켜고 끄기 |

커서 조각이 쉼이면 `?`만 쓸 수 있고 `r?`가 돼. 타브 프렛 글자는 연습 화면과 같은 `buildFretLabel`로 그려: 왼손 운지는 프렛 오른쪽 위 작은 숫자, 오른손은 오른쪽 아래 작은 글자, 아포얀도는 글자 색(주황 굵게, 규칙은 [화면과 조작](ui.md)의 TAB과 지판). 입력판의 아포얀도 단추 글자도 같은 색이라 범례가 돼. 확인 표시가 있는 자리는 경고색이 이겨. 2026-10-19 결정: 처음에는 왼손 운지를 괄호(`7(4)`)로, 주법을 프렛 앞 기호로 붙였는데, 운지가 많은 곡(로망스 1부)에서 칸이 글자만큼 넓어져 한 줄에 마디 하나만 들어갔어. 그래서 첨자로 줄이고, 같은 날 주법도 색으로 바꿔 두 화면 모양을 맞췄어.

### 키보드

입력 칸·목록·대화창에 포커스가 있으면 받지 않아. 글자 키는 `event.code`로 받아 한글 자판에서도 돼.

| 키 | 동작 |
|---|---|
| `0`~`9` | 커서 자리에 프렛. `1`을 누르고 0.7초 안에 `0`·`1`·`2`를 누르면 10·11·12 |
| `Backspace`, `Delete` | 커서 자리 음 지우기. 음이 없고 조각이 쉼이면 쉼 풀기 |
| `←` `→` | 앞·뒤 조각(칸과 마디를 넘어가) |
| `↑` `↓` | 줄 이동(`↑`이 1번 줄 쪽) |
| `R` | 쉼표 켜고 끄기 |
| `Space` | 들어보기 |
| `Ctrl+Z` | 되돌리기 |
| `Ctrl+Y`, `Ctrl+Shift+Z` | 다시 하기 |
| `Esc` | 마디 선택 해제 |

### 마디

- 마디 번호를 누르면 그 마디를 고르고, Shift를 누른 채 누르면 범위로 넓혀. 선택 막대가 고른 범위에 작동해.
- `복제`는 고른 범위를 바로 뒤에 한 번 더 넣어. 반복을 펼칠 때 쓰려고 둔 거야.
- `붙여넣기`는 복사한 마디들을 고른 범위 뒤에 넣고 넣은 마디들을 골라 둬. 칸 수가 달라졌으면 맞춰 자르거나 빈 칸을 붙여. `복제` 뒤에는 원래 고른 범위가 그대로 남아.
- `비우기`는 칸·코드·메모를 지워. `삭제`는 마디를 없애. 모든 마디를 고르면 `삭제`를 막아(마디는 하나 이상 있어야 해).
- 코드 칸을 비우면 `[-]`(코드 없음), `?`를 적으면 `[?]`(앱이 추론)야. 그 밖의 이름은 그대로 적고 앱 검사(`INVALID_CHORD`)를 받아.

### 곡 정보

- 칸 수를 줄이면 넘치는 칸을 잘라 내고, 늘리면 빈 칸을 붙여. 잘려 나간 음이 있으면 몇 개인지 알려 줘.
- 칸을 다시 나누면 시작 위치가 그대로 맞는 조각만 남아(2→4는 다 남고, 2→3은 앞 조각만 남아). 사라진 조각이 있으면 개수를 알려 줘.
- 카포는 문서에 따로 값이 없어. 시트와 같이 설명(또는 제목)의 `Capo 2`·`카포 2` 표기가 카포이고 `parser.getSongCapo`가 읽어. 시트 형식과 같은 곳에 두면 불러오기·내보내기에서 따로 옮길 게 없어서 이렇게 했어. 들려줄 때 그만큼 올려.
- 곡 정보의 `카포` 콤보(`#tiCapoSelect`, 없음·1~12)는 그 표기를 읽어 보여 주고, 고르면 `parser.setSongCapoText`로 제목·설명의 표기를 고쳐(되돌리기 한 단계). 규칙: 표기가 있으면 제목·설명의 표기 전부의 숫자만 바꾸고(`카포: 3` 같은 모양은 그대로), 없으면 설명 끝에 ` · Capo N`을 붙이고, `없음`이면 표기를 지우고 남은 괄호·` · `를 정리해. 설명을 손으로 고쳐도 콤보가 따라와. 2026-10-19 결정: 처음에는 설명에 글로만 적게 했는데, 콤보를 원했어. 저장 형식(설명 글)은 그대로 두고 화면만 콤보로 해서 시트 형식은 안 바뀌어. 표기를 전부 고치는 건 제목과 설명에 둘 다 있을 때 읽는 값(제목이 이김)과 고친 값이 어긋나지 않게 하려는 거야.
- 되돌리기는 마디·음 변경 하나가 한 단계야(최대 200단계). 글자 칸은 입력을 마칠 때(`change`) 한 단계가 돼. 되돌리기 기록은 저장하지 않아.
- 2026-10-19 결정: 되돌리기·다시 하기는 문서와 함께 그 작업 직전의 커서도 되돌려. 처음에는 문서만 되돌려서, 오선 입력에서 `Ctrl+Z` 뒤 바로 이어 넣으면 되돌린 자리가 아니라 뒤쪽 커서 자리부터 들어갔어.

## 텍스트 악보로 바꾸는 규칙

`src/tab-input.js`의 `docToScoreLines`가 한 마디에 한 줄씩 만들어.

1. 음 하나는 `[주법][왼손]음이름옥타브@줄[:오른손][?]`이야. 음높이는 `STRINGS[줄].midi + 프렛`이고, 음이름은 `parser.noteNameForMidi`가 정해. 올림 조표면 `#`, 내림 조표면 `b`, 조표가 없으면 `♯로 적기`·`♭으로 적기` 설정을 따라(`noteLabel` 한 곳). 줄 번호는 항상 붙여. 입력한 줄과 프렛이 연습 화면에도 그대로 나오게 하려고 그래.
2. 한 조각의 음들은 낮은 음부터 `+`로 이어. 음높이가 같으면 굵은 줄(번호가 큰 줄)부터야.
3. 빈 조각은 앞에서 소리가 이어지고 있으면 `-`, 곡 처음이거나 앞이 쉼이면 `r`이야. 마디를 넘어서도 이어져. 쉼으로 고른 조각은 `r`(확인 표시가 있으면 `r?`)이야.
4. 칸 안의 조각을 `/`로 잇되, 줄여도 같은 소리면 줄여. 조각 `i`(둘째부터)가 `-`이거나, `r`이고 바로 앞이 `r`·`r?`이면 "이어지는 조각"이야. 둘째부터 모두 이어지는 조각이면 첫 조각만 남기고, 4분할에서 둘째와 넷째만 이어지는 조각이면 2분할로 줄여. 그래서 `E4/-`는 `E4`, `E4/-/F4/-`는 `E4/F4`, `r/r`은 `r`이 돼.
5. 마디 한 줄은 공통 `serializeScoreMeasures`로 만들어(`[코드] 칸 … | "메모"`). 메모가 비어도 `| ""`가 붙어. 연습 화면의 TSV 복사와 같은 모양이야.
6. 결과 전체를 `parser.validateScore`로 검사해 결과 영역과 해당 마디 카드에 보여 줘. 이 규칙으로 만든 음은 언제나 E2~E5 안이고 같은 줄이 겹치지 않아서, 오류는 코드 이름에서만 나올 수 있어.

입력 화면은 편집할 때 나눈 칸을 그대로 두고, 줄이는 건 내보낼 때만 해.

## 불러오기 (텍스트 → 타브)

`불러오기` 창에 시트 한 행(탭으로 나뉜 5열)이나 악보 텍스트를 붙여 넣어. 내용이 있는 작업을 덮을 때는 먼저 물어봐. 불러오기도 되돌리기 한 단계야.

- 탭이 있으면 첫 줄을 5열 행으로 읽어. 열 수와 칸 수는 `tools/check-score.js`와 같은 기준이고, BPM은 30~240으로 잘라.
- 탭이 없으면 전체를 악보로 읽어. 칸 수는 첫 마디의 칸 개수이고, 제목·BPM·설명은 지금 값을 둬.
- `parser.validateScore` 오류가 있으면 첫 오류를 보여 주고 불러오지 않아.
- 각 음은 `parser.parseNoteToken`으로 읽어 줄·프렛·운지·주법·확인 표시를 그대로 옮겨. `@줄`이 없으면 앱 기본 위치(`FIRST_POS`)를 써.
- 한 조각에서 두 음이 같은 줄에 놓이면(`DEFAULT_STRING_COLLISION`) 불러오지 않고 그 마디와 칸을 알려 줘. 타브 한 줄에는 한 음만 놓을 수 있어서야. 원문에 `@줄`을 적어 다시 불러와.
- `-`는 빈 조각, 쉼(`isRestToken`)은 쉼 조각이 돼. 코드 칸이 `-`면 빈 코드 칸, 생략·`[]`·`[?]`면 `?`야.
- 원문에 `b` 음이 있고 `#` 음이 없으면 변화표를 `♭`으로 맞춰. 조표는 문법에 없어서 불러오면 조표 없음이야.

연습 화면 툴바의 `악보 복사`가 이 형식의 TSV를 복사하니, 내장곡이나 시트 곡도 불러와서 고칠 수 있어. 불러온 뒤 내보내면 모든 음에 `@줄`이 붙고 쉼·유지 표기가 바뀔 수 있지만 소리는 같아(`test/test-tab-input.js`가 내장곡 전부로 확인해).

## 텍스트로 입력

2026-10-19 결정: 입력판의 세 번째 모드 `텍스트로 입력`(`#tiModeText`, `ui.inputMode = 'text'`)은 악보 텍스트를 직접 치고 위의 마디 카드(오선+타브)를 미리보기로 보는 방식이야. 사용자가 문법에 익숙해지면 LaTeX처럼 미리보기를 보며 치는 게 빠를 거라고 해서 넣었어.

- 입력판에 텍스트 편집기(`#tiTextEditor`, 한 줄이 한 마디)와 오류 줄(`#tiTextError`)이 나와. 지판·음 고르는 오선·운지 열은 숨겨(운지는 텍스트에 직접 적어).
- 치다가 0.3초 멈추면 `replaceMeasuresFromText`로 읽어. 맞으면 문서의 마디만 바꿔(제목·칸 수·BPM·설명·조표·`sourceId`는 그대로, 조표가 없으면 변화표는 친 글자의 `b`/`#`를 따라) 카드를 다시 그리고, 틀리면 문서는 마지막으로 맞았던 상태로 두고 오류 줄에 첫 오류(마디 번호 포함)를 보여 줘.
- **친 글자는 앱이 바꾸지 않아.** 편집기 글자는 쓴 그대로(`E4`를 `E4@1`로 고치지 않음) 모드를 바꾸거나 새로고침해도 남아(localStorage `gs.tabInput.text`에 `{raw, baseText, valid}`). 모드를 바꿔도 치던 건 당연히 유지돼야 해. 결과 영역의 `#tiScoreText`는 지금처럼 앱 표준 꼴이야.
- 텍스트 모드로 들어올 때: 저장된 글이 지금 문서에서 나온 것(`baseText`가 지금 문서 텍스트와 같음)이면 그 글을 그대로 보여 줘. 그사이 다른 모드나 되돌리기로 문서가 바뀌었으면 지금 문서 텍스트를 보여 주고, 저장된 글이 오류 상태(`valid: false`, 문서에 반영 못 한 글)였으면 `이전 입력 복원`(`#tiTextRestoreBtn`)로 다시 꺼낼 수 있어.
- 편집기에서 글자 커서가 있는 줄(빈 줄은 세지 않음)의 마디로 문서 커서를 옮기고 그 카드가 보이게 스크롤해. 텍스트 모드로 들어오면 지금 커서 마디의 줄 첫머리에 글자 커서를 둬.
- 텍스트 모드에서는 카드로 문서를 바꾸는 조작(코드·메모 칸, 타브 자리 입력·지우기, 선택 막대 마디 작업, `+ 마디 추가`)을 막아. 카드를 누르면 커서만 옮기고 편집기 글자 커서를 그 마디 줄로 보내. 고치는 곳이 둘이면 카드에서 고친 메모를 편집기의 옛 글이 다음 반영 때 덮어쓰기 때문이야. 곡 정보와 되돌리기·다시 하기는 그대로 되고, 바뀌면 위 규칙대로 편집기를 다시 채워. 같은 이유로 편집기 밖에 포커스가 있을 때는 `Ctrl`/`Cmd` 조합 말고 단축키를 받지 않아(숫자·`Delete`·`R`이 카드를 고치지 않게). 그래서 이때 `Space` 들어보기는 안 되고 `들어보기` 단추는 돼.
- 마디 줄 번호는 빈 줄을 빼고 세. 빈 줄 위면 바로 앞 마디, 마디 수보다 크면 마지막 마디야. 한 줄에 `//`로 여러 마디를 적으면 줄과 마디 번호가 어긋나니 한 줄에 한 마디로 써.
- 되돌리기: 텍스트로 처음 반영할 때 한 단계를 기록하고, 텍스트 모드를 떠나거나 편집기에서 포커스가 빠질 때까지는 더 기록하지 않아(한 번 고친 흐름이 한 단계). 편집기 안의 `Ctrl+Z`는 브라우저 기본 글자 되돌리기야. `되돌리기` 단추나 칸 수 변경처럼 문서가 밖에서 바뀌면 편집기를 지금 문서 텍스트로 다시 채워.

## 연습 화면에서 가져오기

2026-10-19 결정: 연습 화면의 `악보 편집`과 마디 `편집`은 `{sourceId, title, beats, bpm, badge, lines, key, measure, savedAt}`을 localStorage `gs.tabInput.open`에 쓰고 이 화면으로 와. 이 화면은 부팅 때 10분 안에 쓴 값이면 읽고 지운 뒤, 불러오기와 같은 규칙(`scoreToDoc`)으로 문서를 만들고 `sourceId`·조표를 붙여. 지금 작업에 내용이 있고 넘어온 악보와 다르면 바꿀지 물어보고(되돌리기 한 단계로 돌아올 수 있어), 커서를 넘어온 마디 첫 조각에 둬. 읽을 수 없는 악보(같은 줄 겹침 등)면 지금 작업을 그대로 두고 이유를 알려 줘. 곡 정보 아래에 어느 곡을 고치는 중인지(`#tiSourceInfo`) 보여 줘. `새 악보`와 `불러오기`는 `sourceId`를 지워.

## 저장과 넘기기

- 2026-10-19 결정: 작업 중인 악보 하나를 localStorage `gs.tabInput.doc`에 자동 저장해(변경마다, 글자 입력은 0.3초 뒤). 연습 화면은 텍스트 악보를 저장하지 않는데, 그건 내장곡·시트 원본의 사본이 원본과 어긋나지 않게 하려는 거야. 입력 화면의 작업은 원본이 없는 새 글이고, 한 곡을 마우스로 찍는 데 오래 걸려서 새로고침 한 번에 날아가면 안 돼. 저장에 실패하면 곡 정보 줄에 알려 줘. 오래 둘 악보는 TSV로 복사해 시트에 넣어.
- 저장된 값의 모양이 틀리면 새 악보로 시작하고 그렇다고 알려 줘.
- 입력판 설정(`입력 시 자동 이동`, `소리`, 접기, 휴대폰 운지 펼침)은 `gs.tabInput.ui`에 둬.
- `시트용 TSV 복사`는 공통 `formatSongToSheetTsv`로 5열 행을 만들어. 설명이 비면 `악보 입력`을 넣어.
- `연습 화면에서 열기`는 `{sourceId, title, beats, bpm, badge, lines, key, savedAt}`을 `gs.tabInput.handoff`에 쓰고 `index.html`로 가. 연습 화면은 부팅 때 10분 안에 쓴 값이면 읽고 지운 뒤, `sourceId`의 곡이 있으면 그 곡의 수정 초안(악보와 조표만 바꾸고 제목·BPM·설명은 원래 곡 것), 없으면 새 임시 악보를 만들어 열어. 출처가 `tab-input`이라 떠날 때 경고하지 않아(원본이 입력 화면에 저장돼 있어서야). 상태 줄에는 악보 입력에서 고친 초안이라고 적어.
- 오류가 있으면 복사와 넘기기 버튼을 막아. 결과의 검사 목록은 오류가 없으면 `오류 없음`, 경고가 있으면 그 뒤에 `경고 · …` 줄을 붙여.

## 소리

입력판과 타브 클릭은 `audio.js`의 `playGuitarNote`로 그 줄의 음을 들려줘. 음높이는 `soundingMidi(음, 카포)`야. 음색과 효과는 연습 화면 설정(localStorage `gs.state`)을 읽기만 하고 고치지 않아. 그러려고 연습 화면 `app.js`에 있던 설정 상태(`appState`)와 오디오 런타임 전역(`actx` 등)을 `src/app-state.js`로 옮겨 두 화면이 같이 불러. `audio.js`의 공명현 경로가 전역 `curCapo()`를 부르는데 이 함수는 `app.js`에 있어서, 입력 화면은 `tab-input-ui.js`에서 `docCapo`를 돌려주는 `curCapo`를 따로 정의해.

곡 전체 재생은 입력 화면에 두지 않아. `연습 화면에서 열기`로 연습 화면의 재생·메트로놈을 써.

### 문서 모양

```text
doc = { version: 1, title, beats, bpm, description, accidentals: 'sharp' | 'flat', key: -5~5, sourceId: null|문자열, measures: [measure] }
// sourceId가 없는 저장 문서는 null로 읽어(연습 화면에서 가져오기 전의 작업)
// key가 없는 저장 문서는 0으로 읽어(2026-10-19 조표를 더하기 전 작업)
measure = { chord, memo, cells: [cell] }          // cells 개수 = beats
cell = { slots: [slot] }                          // slots 개수 = 나눈 수 1~4
slot = { rest, restUncertain, notes: [note|null × 6] }   // notes[0]이 1번 줄
note = { fret: 0~12, lh: null|0~4, rh: null|'p'|'i'|'m'|'a', art: null|'!'|'~', uncertain }
```
